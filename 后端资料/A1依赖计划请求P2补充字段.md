# A1 串行依赖计划：请求 P2 明确的最小字段

## 背景

A1 已实现 `dependsOn` DAG 调度：只有全部前置步骤成功才解锁下一波；失败会阻断所有传递下游；已派发步骤不会重复派发。

当前 r3 契约存在一个恢复缺口：

- 步骤登记响应有 `clientStepKey / stepId / prepareKey`；
- 委派响应有 `childTaskId / parentTaskId / targetAgent / status`；
- `CHILDREN_FINISHED` 回调有 `dependencyResults[].taskId`；
- 但冻结 schema 没有规定 `childTaskId` 对应哪个 `clientStepKey`，也没有规定回调中的 `planSteps` 必须携带依赖关系。

A1 不能按领域或 Agent 猜映射，因为同一计划允许两个步骤都交给 A2 或同一领域。

## 建议的最小契约

P2 在 `context.planSteps[]` 中稳定回传：

```json
{
  "clientStepKey": "s2",
  "stepId": "step-002",
  "dependsOnClientStepKeys": ["s1"],
  "state": "RUNNING",
  "actionId": "action-002",
  "childTaskId": "child-002"
}
```

字段要求：

- `clientStepKey`、`stepId`：必填且在根任务内唯一。
- `dependsOnClientStepKeys`：必填数组，可为空；只能引用同一计划步骤。
- `state`：至少区分 `PLANNED / RUNNING / SUCCEEDED / FAILED / CANCELLED / EXPIRED`。
- `actionId`：动作准备后填写，未准备时为 `null`。
- `childTaskId`：委派成功后填写，未委派时为 `null`；与 `dependencyResults[].taskId` 一一对应。

如果 P2 不希望在 `planSteps` 保存依赖，也可以仅保证 `clientStepKey ↔ childTaskId`，但 A1 仍需另一个由 P2 持久保存并在恢复时回传的依赖字段，不能依赖 A1 进程内存。

## A1 收到字段后的行为

1. 以 `childTaskId` 对照 `dependencyResults[].taskId`，确定完成的 `clientStepKey`。
2. 只把 `SUCCEEDED / PARTIALLY_SUCCEEDED` 视为满足前置条件。
3. `FAILED / CANCELLED / EXPIRED` 阻断所有传递下游。
4. 已有 `actionId` 或 `childTaskId` 的步骤绝不重新准备、重新委派。
5. 字段缺失、重复或互相矛盾时停止自动执行，返回核查状态，不猜测映射。

## 请 P2 队友确认

- 是否接受上述字段名；或提供语义等价的现有字段。
- `PARTIALLY_SUCCEEDED` 是否允许解锁必需依赖；A1 当前建议允许整合但最终根任务标记为部分成功。
- P2 是否在进程重启后仍持久保存并回传这些字段。
