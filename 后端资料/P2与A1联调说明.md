# P2 与 A1 联调

前端继续发 `POST /api/v3/agent/messages`，拿到 `taskId` 后查询任务。P2 的任务执行器调用 A1 的 `POST /internal/v3/messages`，通过调用收据和取消接口处理超时与取消。A1 的 8095 是过渡页面服务，P2 的对接地址填 A1 的 v3 服务（同机默认联调端口 8093）。

## 启动

1. A1 负责人启动 v3 服务并提供联调地址。两边同机时可以用 `http://127.0.0.1:8093`，跨机器使用 P2 可访问的 HTTPS 根地址。先确认 `GET /health` 可达。探活只验证进程存活。
2. 在 P2 本地 `.env` 设置 `AGENTS_MODE=http`、`AGENT_A1_URL`、`AGENT_A1_API_KEY`。A1 入站校验的 Key 与 P2 发送的 `X-Agent-Key` 对齐。如果 A1 回调 P2，其文档中的 `A1_AGENT_KEY` 使用 P2 分配给 A1 的 Key，`A1_P2_URL` 填 A1 可访问的 P2 地址。密钥通过私下的安全渠道配置。
3. P2 的 HTTP 模式要求 A1、A2、A3 三个独立 Key。本地 `init-env.ps1` 会生成演示配置。首轮仅验证 A1 文本，需要真实委派时再配置 A2、A3 的地址和配套 Key。
4. 重启 P2 后从仓库根目录执行 `pwsh -NoProfile -File .\p2-backend\scripts\smoke-a1.ps1`。跨机器加 `-A1Url <A1地址>`。同时在 A1 的服务日志或调用收据里核对对应调用，确认回复来自真实旅游处理。

## 首轮核对项

- A1 接收 v3 任务正文与 `X-Agent-Key`、`X-Trace-Id`。P2 需要 `code: "OK"`、`data` 为 v3 结果对象，并校验任务、调用和版本的关联字段。先走一条可以完成的旅游文本请求。
- A1 文档中的模型及领域调用时限可能超过 P2 本轮 HTTP 60 秒、任务调用期限约 65 秒。先测实际耗时；超时时检查调用收据和后续交付规则。
- 委派、步骤登记、准备动作和确认分别验收。A1 文档里待对齐的工具入口是 P2 的 `POST /internal/agent/v3/tools`，请求字段和权限按 P2 工具契约逐项对照。
- 图片、反诈异步结果、真实 A2/A3 委派分别验收。8093 联调壳返回成功只说明报文交互可用，真实业务结果还需用领域服务验证。
