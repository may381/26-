# P2 后端接口文档 v3.0

更新日期：2026-10-29。给前端、Agent负责人和测试同学使用。

这份文档是P2接口的v3.0开发目标。原有28项业务操作迁移到v3.0路径；Agent任务查询、取消、确认等新增操作见统一协议。本文不表示这些v3路径已经部署。

本版按平台统一接口协议 v3.0 迁移。所有P1调用P2的接口统一使用`/api/v3/...`路径和`{code,message,data}`响应；档案、景点、路线等仍保留各自业务字段。Agent消息、任务、委派、确认和恢复按统一协议定义。v3.0是唯一开发目标，当前代码需要改造后再启用。

## 先把接口调通

**v3.0服务尚未部署，当前旧Swagger不能用于测试本文接口。**完成P2改造后，由启动配置提供后端地址和Swagger地址；下面的路径均为相对路径，测试时再拼接该环境的主机地址。

本文示例省略主机地址，例如GET /api/v3/profile，实际是在后端地址后面接这段路径。

### 部署v3后：在Swagger里填演示身份

点Authorize，分别填写两个值，并分别点击对应的Authorize按钮。以老人身份为例：

```http
X-Mock-Actor-Id: u100
X-Mock-Actor-Role: ELDER
```

| 你要模拟谁 | actorId | actorRole |
|---|---|---|
| 老人本人 | u100 | ELDER |
| 另一个老人，用于越权测试 | u101 | ELDER |
| 家属 | family-operator-001 | FAMILY |
| 另一位家属 | family-operator-002 | FAMILY |
| 景区处理人员 | scenic-operator-001 | SCENIC |
| 官方处理人员 | official-operator-001 | OFFICIAL |
| 管理员 | admin-operator-001 | ADMIN |

这是本地演示身份，不是真实账号登录。切换身份时两个值都要改，不能只改角色。

### 第二步：分清几种ID

| 名称 | 举例 | 用在哪里 |
|---|---|---|
| userId | u100 | 表示业务属于哪位老人 |
| Profile.id | 档案UUID | 档案本身的编号，不能拿它代替userId |
| familyId | 创建关系返回的data.id | 批准、绑定、改权限和撤销家属关系 |
| tripId | 创建游览返回的data.id | 查游览、结束、反馈、查游后详情 |
| helpId | 创建求助返回的data.id | 查询、受理和解决求助 |
| routeId | r1 | 选择路线、查询地图 |
| spotId | spot-003 | 景点详情、求助位置 |

正文里写的{familyId}、{tripId}和{helpId}都是占位符，操作时换成接口实际返回的ID。不要把花括号或占位符本身发给后端。

请求头说明“谁在操作”，userId说明“操作谁的数据”。两者都需要，Authorize不会自动替你填写userId。

### 第三步：看懂返回结果

成功统一HTTP 200，创建接口也一样：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {}
}
```

code是业务标识，不是HTTP状态码。data里放业务结果，可能是对象或数组。message可能包含演示说明，不要用它代替Agent回复。

失败示例：

```json
{
  "code": "CONFLICT",
  "message": "已有进行中的游览",
  "data": null
}
```

带JSON正文的请求使用Content-Type: application/json。上传音频用multipart/form-data，具体见第24项。

JSON字段大小写和类型必须正确，例如true不能写成字符串"true"。除响应中可兼容的新字段外，请求不要自行加字段。时间使用ISO 8601格式，例如2026-10-29T01:00:00Z，Z表示UTC，前端显示时换算成本地时间。

下面每个接口都说明怎么填和看哪些返回字段。完整字段、类型和限制可查同目录的[字段附录](P2接口字段附录_v3.0.md)。

## 一、老人档案：先建档，再开始游览

本节都使用u100 / ELDER，userId填u100。

### 01 保存或修改档案

`PATCH /api/v3/profile?userId=u100`

第一次必须提交下面全部十项字段。已有档案时，只提交想修改的字段即可。

```json
{
  "nickname": "接口测试老人",
  "age": 68,
  "residence": "演示城市",
  "language": "普通话",
  "walkSpeed": "MEDIUM",
  "walkDurationMin": 60,
  "avoidSteps": true,
  "interests": ["历史"],
  "interactionPreference": "VOICE",
  "emergencyContacts": []
}
```

| 字段 | 怎么填 |
|---|---|
| nickname | 昵称，非空，最多100字符 |
| age | 整数，1～150 |
| residence | 居住地，非空，最多200字符 |
| language | 语言，非空，最多50字符 |
| walkSpeed | SLOW慢、MEDIUM中、FAST快 |
| walkDurationMin | 可接受步行时长，整数1～1440，单位分钟 |
| avoidSteps | 是否尽量避台阶，true或false |
| interests | 兴趣数组，最多30项，每项非空且最多100字符；可用[]清空 |
| interactionPreference | VOICE语音或TEXT文字，只表示偏好，不会自动生成音频 |
| emergencyContacts | 紧急联系人数组，最多10项；可用[]清空 |

联系人每项为{"name":"演示联系人","phone":"DEMO-NOT-A-PHONE","relation":"女儿"}。name和relation最多100字符，phone最多40字符，三项都不能为空。测试不要填真实电话。

修改示例：{"walkDurationMin":70}。未传的字段保留原值，数组整体替换；不接受null、未知字段或空对象。返回data是最新完整档案，含只读id；不要把id提交回来。

### 02 读取档案

`GET /api/v3/profile?userId=u100`

没有请求正文。返回档案id及上面十项内容。尚未建档返回404；家属不能用这个接口读取老人完整档案，家属走第21项摘要接口。

## 二、景点和路线：先选路线，地图按需加载

### 03 查景点列表

`GET /api/v3/spots?scenicId=qingfeng`

所有已认证演示角色可调用。scenicId可不传，不传查当前数据源全部景点。

返回data为数组。每项包括id、scenicId、name、description、descriptionAvailable、location、coordinateSystem、source、updatedAt、verifiedBy。location含lat和lng。

当前演示景点spot-001～spot-006。介绍缺失时description为null、descriptionAvailable为false，页面显示“介绍待补充”，不要当作接口失败。

### 04 查一个景点和它关联的设施

`GET /api/v3/spots/spot-003`

可选query：scenicId=qingfeng。返回与列表相同的景点字段，再增加facilities数组。设施含id、name、type、spotId、location、coordinateSystem及来源信息。

type可能是TOILET厕所、BENCH座椅、MEDICAL医疗点、EXIT出口、SERVICE_DESK服务台。这里列出的是关联设施，不表示最近距离、实时营业或一定可达。无设施返回[]；景点不存在返回404。多景区出现同名ID时，未限定景区可能返回409，此时带scenicId再查。

这两个景点接口的坐标是WGS84，不能直接当成高德GCJ-02坐标使用。source为MOCK表示演示数据，不是已完成现场核验。

### 05 查路线和推荐结果

`GET /api/v3/routes?userId=u100`

建议使用老人本人身份。userId可选；传入后读取本人档案计算推荐，没建档返回404。不传时按默认偏好计算，不表示个性化推荐。

可选参数walkDurationMin（1～1440的整数）、avoidSteps（true/false），只覆盖本次推荐，不修改档案。

返回data.routes数组。每条包含id、name、spots、segments、source、updatedAt、verifiedBy、recommended、reason。

spots是景点ID数组；名称和介绍到第03/04项查。recommended表示本次是否推荐，reason说明推荐理由。segments包含起终点、台阶数、坡度、预计分钟、休息设施及来源信息。推荐结果不是路线已被选择，更不是已开始游览。

当前演示路线包含r1等三条；实际应从返回值取routeId。

### 06 查路线的高德地图

`GET /api/v3/routes/r1/map`

已认证用户可调用。不传正文，也不需要userId。P2调用高德服务，需要当前项目.env配置AMAP_WEB_SERVICE_KEY。

返回data中的路线信息、provider、coordinateSystem、spots和legs等字段供地图展示。精确字段见附录第06项。地图坐标为GCJ-02，高德步行路径不等于已经核验无障碍或适老道路；注意accessibilityVerified等提示。

缺Key或高德调用失败一般返回502。先跳过本项，不会阻塞景点列表等接口测试。密钥由后端保管，不要传给前端或发到群里。

## 三、家属授权：建关系、批准、绑定账号、开权限

第07～12项都由老人本人操作，身份u100 / ELDER。所有接口的userId都必填。

### 07 创建关系

`POST /api/v3/family-relations?userId=u100`

```json
{
  "name": "接口测试家属",
  "relation": "女儿",
  "phone": "DEMO-NOT-A-PHONE"
}
```

name、relation非空且最多100字符，phone非空且最多40字符。保存返回的data.id作为familyId。新关系status=PENDING，四个权限都是false，不会立即获得访问权。

### 08 看已有关系

`GET /api/v3/family-relations?userId=u100`

data是关系数组。每项含id、name、relation、phone、permissions和status。先看status再操作，不要对同一条记录连续点击批准或撤销。

### 09 老人批准关系

`POST /api/v3/family-relations/{familyId}/approve?userId=u100`

无正文。PENDING变ACTIVE，返回更新后的关系。批准不自动打开权限，也不自动识别哪个家属账号。重复批准通常返回409。

### 10 绑定演示家属账号

`POST /api/v3/family-relations/{familyId}/mock-account?userId=u100`

```json
{
  "familyActorId": "family-operator-001"
}
```

先批准为ACTIVE再绑定。data返回familyRelationId、userId和familyActorId。相同绑定重复提交可成功；更换已绑定身份或同一老人已有冲突绑定返回409。撤销旧关系后才可把该账号关联到新关系。

这是本地联调用的显式绑定，不是真实手机号邀请或账号验证。家属不能自己调用它获得授权。

### 11 修改共享权限

`PATCH /api/v3/family-relations/{familyId}/permissions?userId=u100`

```json
{
  "shareLocation": false,
  "shareProgress": true,
  "shareAlert": true,
  "remotePlanning": false
}
```

至少提交一项，值只能是boolean。正文直接放开关，不要再包permissions。未传的开关保留，不接受null。关系必须ACTIVE。

| 开关 | 含义 | 目前效果 |
|---|---|---|
| shareLocation | 共享位置 | 当前没有真实位置采集，打开后也不会凭空产生位置 |
| shareProgress | 共享游览情况 | 可读活动游览摘要；实际已游和预计到达尚未采集 |
| shareAlert | 共享求助告警 | 可读求助摘要和当前关系的模拟通知 |
| remotePlanning | 允许远程规划 | 当前没有公开的家属远程规划流程 |

四个开关互不替代。返回data为更新后的家属关系。

### 12 撤销关系：放到最后测试

`POST /api/v3/family-relations/{familyId}/revoke?userId=u100`

无正文。成功后status=REVOKED，四个权限全部false。家属下次读取该老人摘要和通知会被拒绝。不能继续批准这条已撤销记录来代替新建关系。

## 四、游览：开始、查看、结束

### 13 开始一次游览

`POST /api/v3/trips?userId=u100`，老人本人调用。

```json
{
  "routeId": "r1"
}
```

需要先建档。返回示例：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "id": "11111111-1111-4111-8111-111111111111",
    "userId": "u100",
    "routeId": "r1",
    "status": "ACTIVE"
  }
}
```

示例UUID只演示格式，后续必须使用实际返回的data.id作为tripId。同一个老人同时只能有一次ACTIVE游览；已有活动游览返回409。创建时保存路线快照。

### 14 查本次游览

`GET /api/v3/trips/{tripId}?userId=u100`

老人本人调用。返回id、userId、routeId、status。不存在或不属于本人返回404。这不是实时定位或逐景点进度接口。

### 15 结束游览

`POST /api/v3/trips/{tripId}/finish?userId=u100`

老人本人调用，无正文。ACTIVE变FINISHED，返回更新后的游览。结束后才能查游后记录、提交反馈。当前没有公开取消游览接口。

## 五、求助：创建、受理、解决

通知目前为站内模拟，不代表家属、景区或官方已经真实收到消息。

### 16 创建求助

`POST /api/v3/help-events`，老人本人调用。

建议带请求头Idempotency-Key，例如manual-help-20261029-01。query的userId可省略；如传了，必须与正文一致。

```json
{
  "userId": "u100",
  "tripId": null,
  "type": "GENERAL",
  "location": {
    "spotId": "spot-003"
  },
  "locationNote": "人工接口测试，非真实求助"
}
```

type必填：SOS紧急求助、LOST迷路、UNWELL身体不适、GENERAL一般求助。tripId可选，填时必须属于当前老人。

至少有location或非空locationNote；locationNote最多500字符。location有两种写法，二选一：{"spotId":"spot-003"}，或{"lat":22.581,"lng":114.0608}。不能同时传spotId和经纬度；纬度-90～90，经度-180～180。

返回data是求助对象，保存id作为helpId。businessStatus初始OPEN。其他字段：userId、tripId、type、location、locationNote、notifications、createdAt、updatedAt。notifications每项有recipientType、recipientId、status，是模拟收件状态，不是求助处理状态。

### 17 查求助列表

`GET /api/v3/help-events?userId=u100`

老人只能查本人。SCENIC、OFFICIAL、ADMIN可查处理侧记录，userId可选用于筛选，不传可能看到更大范围。FAMILY不能调用本接口，家属走摘要和通知接口。

返回data为求助对象数组，字段与创建结果相同。目前没有分页参数。

### 18 查单条求助

`GET /api/v3/help-events/{helpId}?userId=u100`

权限同列表；userId可选。返回单条求助对象。更新后的处理状态以这个GET为准，不能靠之前创建响应猜测最新状态。

### 19 工作人员受理

`POST /api/v3/help-events/{helpId}/acknowledge`

切换为scenic-operator-001 / SCENIC，或OFFICIAL、ADMIN。userId可选，用于限定目标。无正文。

OPEN变ACKNOWLEDGED，同时记录实际接单人。已经受理或解决再受理返回409。返回更新后的求助对象。

### 20 工作人员解决

`POST /api/v3/help-events/{helpId}/resolve`

由第19项的实际接单人调用，ADMIN也可处理。无正文，userId可选。ACKNOWLEDGED变RESOLVED。

未接单就解决通常409，换另一个普通处理人员解决通常403。不要把接单人ID填进正文来冒充。

### 同一次求助如何重试

Key使用1～128位英文字母、数字或点、下划线、冒号、短横线。同一动作沿用同一个Idempotency-Key和相同正文，24小时内返回首次创建结果；同Key不同正文409。新动作才换Key。重复创建返回的仍是首次快照，最新状态用第18项查询。直接创建的Key目前可选，但前端应主动携带；Agent创建求助则必须在原始对话请求中带Key。

## 六、家属读取：先确认绑定和开关

### 21 家属看老人摘要

`GET /api/v3/family/elder?userId=u100`

切换为family-operator-001 / FAMILY。这里userId仍填老人u100，不是家属账号。

前提：关系ACTIVE、已关联当前家属身份。返回userId、profileId、nickname、familyRelationId、permissions、trip、location、locationAvailable、helpEvents、notice。

| 数据 | 什么时候有 |
|---|---|
| trip | shareProgress=true且存在活动游览时返回摘要，否则null |
| helpEvents | shareAlert=true时返回最近20条摘要，无记录为[]；没授权为null |
| location | 当前始终null，locationAvailable=false |
| trip里的实际进度 | 当前progressAvailable=false，已游点/下一点/预计结束时间为null |

不会返回完整档案、住址和紧急联系人。没有有效关联或关系被撤销返回404。前端撤权后要清理旧缓存，不要继续展示先前读取的数据。

### 22 家属收通知

`GET /api/v3/notifications?userId=u100&limit=20`

同一FAMILY身份。需要有效关联且shareAlert=true；关掉shareAlert返回403，关系无效返回404。limit可选，默认20，范围1～100。

返回data数组，按通知创建时间倒序。字段：id、helpEventId、type、helpType、businessStatus、status、deliveryMode、createdAt、updatedAt。

type为HELP_OPEN、HELP_ACKNOWLEDGED、HELP_RESOLVED之一；同一求助的不同阶段可能各有一条通知。businessStatus是当前求助处理状态，status是该通知投递状态。deliveryMode目前MOCK。

只读当前家属关系自己的收件记录，不显示其他家属通知。当前没有已读操作，也没有全历史分页。

## 七、Agent和语音：文字先问Agent，再合成回复

### 23 给Agent发送消息（v3.0）

`POST /api/v3/agent/messages`，老人本人调用。这个接口只负责接收消息并创建/关联任务，不等待Agent全部处理完。

请求正文使用统一协议的`MessageRequest`：包含`protocolVersion: "3.0"`、`userId`、`conversationId`、`continueTaskId`、`input`和`context`。新对话的conversationId、continueTaskId传null；继续任务时带P2返回的ID。完整模板、追问回答和幂等要求见《P2平台统一接口协议 v3.0》。

成功返回`{code:"OK",message,data}`，其中data提供conversationId、messageId、taskId和任务状态；这表示“已接收”，不表示答案已经生成。前端随后查询`GET /api/v3/agent/tasks/{taskId}`取得回复、业务卡片、待确认项和子任务进度。不要继续读取v2格式的`data.reply.text`作为本接口的即时响应。

Agent消息路径不再使用旧的`/api/agent/messages`格式；新开发统一按v3.0协议。

### 24 语音转文字

`POST /api/v3/speech/transcriptions?userId=u100`，老人本人调用。

上传方式是multipart/form-data，不是JSON。表单字段audio选择音频文件，必填，大小1字节～10MiB。userId可省略，此时取当前老人。

支持WAV、MP3、WebM、OGG、MP4/M4A对应音频MIME，后端也检查文件头。不能只修改文件后缀。浏览器使用FormData时不要手动写Content-Type，浏览器会补boundary。

当前返回：

```json
{
  "code": "OK",
  "message": "语音演示占位：未识别或生成真实音频",
  "data": {
    "text": "【演示转写，未识别音频内容】厕所在哪"
  }
}
```

注意这里仍读data.text，因为这是转写结果，不是Agent对话。当前是固定mock文字，不识别用户真正说了什么。

### 25 文字转语音

`POST /api/v3/speech/syntheses?userId=u100`，老人本人调用。

```json
{
  "text": "前方有休息点，可以稍作休息。",
  "speechRate": 0.8
}
```

text必填、非空、最多2000字符；speechRate必填，0.5～1.5。userId可省略取当前老人。

返回data为{"audioUrl":null}，message同样说明mock。当前不生成真实音频。以后接入真实语音服务才可用非空地址播放。Agent最多回复4000字符，不能不分段就直接提交给2000字符限制的合成接口。

文本提问：前端发文字到第23项，取得回复，再把回复文字发给第25项。

语音提问：前端录音调用第24项，取转写文字发第23项，再把Agent回复文字发第25项。三次请求由前端串起来；文字转语音不再交给Agent生成答案。

## 八、游后记录与反馈

本节只允许老人本人调用，userId必填。

### 26 看游后记录列表

`GET /api/v3/travel-records?userId=u100&limit=20`

只返回已经FINISHED的游览。limit可选，默认20，范围1～100。第一页不要传cursor；下一页把上次data.nextCursor原样传回，null表示没有下一页，不要自己解析或拼游标。

返回data包含items和nextCursor。items每条有id、tripId、userId、routeId、routeName、source、startedAt、finishedAt、durationSeconds、feedbackSubmitted。

记录id和tripId目前是同一个游览UUID，反馈id则不同。durationSeconds是开始到结束的历时，不代表连续步行时长。

### 27 看游后记录详情

`GET /api/v3/travel-records/{tripId}?userId=u100`

返回列表字段中的基本信息，以及scenicId、status、plannedSpotIds、visitedSpotIds、visitedEvidence、progressAvailable、routeSnapshot、feedback、notice。详情用feedback对象，不是列表的feedbackSubmitted标志。

routeSnapshot是开始游览时保存的路线。plannedSpotIds是计划景点，当前visitedSpotIds=[]、visitedEvidence=NONE、progressAvailable=false，不代表已经真实到访。feedback尚未提交时null；有反馈则返回其对象。未结束的游览在这里返回404。

### 28 提交本次反馈

`POST /api/v3/trips/{tripId}/feedback?userId=u100`

必须带请求头Idempotency-Key，例如manual-feedback-20261029-01。

```json
{
  "effort": "TIRED",
  "comfortableWalkMin": 40,
  "note": "人工接口测试，后半程感觉有些累"
}
```

effort必填：EASY轻松、COMFORTABLE舒适、TIRED疲惫。comfortableWalkMin可选，为1～1440的整数，表示用户觉得合适的步行分钟数。note可选，最多500字符，空白按无备注处理。

返回id（反馈UUID）、tripId、userId、effort、comfortableWalkMin、note、createdAt、profileUpdated、memoryWritten。后两个目前都是false，反馈不会自动修改档案或写入长期记忆。

每次已结束游览只接受一份反馈。相同Key、相同正文重试返回相同反馈；同Key异正文或换Key重复提交同一次游览都409。游览未结束409，没带Key400。当前没有反馈修改或删除接口。

## 九、按这个顺序测一轮

1. 用老人身份保存并读取档案：01、02。
2. 看景点和路线：03、04、05；有高德Key再测06。
3. 创建家属关系、批准、绑定账号、打开进度和告警权限：07、08、09、10、11。
4. 创建并查询游览：13、14，保存tripId。
5. 测Agent和语音：23、24、25。语音目前只验证调用格式。
6. 创建并查求助：16、17、18，保存helpId。
7. 切换家属身份查摘要和通知：21、22。
8. 切换景区身份受理并解决：19、20；可切家属再查通知。
9. 切回老人，结束游览：15。
10. 查记录、提交反馈、再查详情：26、27、28、27。
11. 最后撤销关系：12，再切家属查21、22，应返回404。

每一步先看是否成功，再使用本轮返回的ID。不要重用上一轮已撤销的familyId、已解决的helpId或已提交过反馈的tripId。

## 十、报错时先看这张表

| HTTP / code | 常见原因 | 先做什么 |
|---|---|---|
| 400 / INVALID_ARGUMENT | 参数漏填、字段类型错、混用Agent旧格式 | 检查Swagger必填项和请求正文 |
| 400 / UNSUPPORTED_PROTOCOL_VERSION | Agent版本缺失或不是3.0 | 在Agent请求正文填写字符串protocolVersion=3.0 |
| 401 / UNAUTHORIZED | 身份头缺失或账号角色配错 | 重新填两个Authorize值 |
| 403 / FORBIDDEN | 用家属查完整档案、越权、处理人不匹配 | 检查身份、业务userId和共享开关 |
| 404 / NOT_FOUND | 没建档、ID错误、无有效家属关系、游览未结束 | 先补前置步骤，确认用的是本轮ID |
| 409 / CONFLICT | 重复状态操作、已有ACTIVE游览、绑定或幂等冲突 | 查当前状态，不要反复点击提交 |
| 502 / UPSTREAM_ERROR | 高德失败、Agent失败或回复不合协议 | 查看后端服务状态和上游配置，不盲目重复写操作 |
| 504 / UPSTREAM_TIMEOUT | Agent上游调用超时 | 求助先查是否已创建，再按同Key核查 |

“无法访问网站/连接被拒绝”是服务或端口问题，不是接口返回400/500。先确认数据库、后端进程和启动端口。Swagger里显示Undocumented只表示该状态没逐条登记在页面里，不等于请求没到后端。

前端本地开发可以通过开发服务器把`/api/v3`代理到本机已部署的v3服务。当前v2服务地址和Swagger不能验证本文的v3接口；v3部署后再填写实际地址。浏览器跨域直连的CORS白名单需按准确来源配置，不要使用`*`。

## 十一、哪些还不能当成真实能力

- 当前Agent适配和运行服务尚未全部迁移到v3；所有负责人按统一协议v3.0开发和联调后再启用。
- 语音转写不识别真实内容，合成不产生音频。
- 求助业务状态可以流转，但通知不是短信、微信或真实官方触达。
- 家属不能看到尚未采集的真实位置、实际已游景点和预计到达时间。
- 景点/路线当前有MOCK数据，介绍缺失不会自动补造。
- 没有公开的长期记忆写入、家属远程规划、进度上报或路线中途调整接口。
