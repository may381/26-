# 安知·多模态反诈智能助手

## 详细需求分析文档

**文档版本：** V1.0

**整理日期：** 2026-09-29

**项目定位：** 面向个人用户、家庭监护和校园/社区场景的本地化多模态反诈辅助工具。

**当前技术形态：** React + TypeScript + Vite 前端，FastAPI 后端，SQLite 数据库，Ollama 本地大模型，BGE-M3 向量检索，Faster-Whisper 语音转写。

---

## 1. 项目概述

### 1.1 项目背景

网络诈骗从传统电话和短信逐渐扩展到即时通信、社交媒体、图片海报、语音消息和视频内容。诈骗者通常通过冒充身份、制造紧迫感、诱导保密、承诺高收益、要求先付款或要求提供验证码等方式推动受害者执行操作。

现有反诈工具更多依赖号码、网址、账号和黑名单比对，而用户在微信、QQ、社交平台或线下转述中遇到的风险，往往发生在号码进入黑名单之前。因此，本项目重点解决“用户已经看到可疑内容，但还没有确定是否应该相信”的判断问题。

### 1.2 产品定位

安知不是公安执法系统、支付拦截系统或紧急止付系统，而是一个内容风险识别和家庭协同辅助工具。系统接收用户主动提交的文字、图片、音频或视频内容，结合用户角色、历史风险记忆和反诈知识库，输出可解释的风险判断、防御建议和监护人联动信息。

### 1.3 核心目标

1. 支持文字、图片、音频和视频等多模态输入。
2. 对诈骗话术、图片文字、语音转写内容和视频关键帧进行分析。
3. 输出低风险、中风险、高风险分级结果。
4. 输出诈骗类型、证据摘录、相似案例和防御建议。
5. 将高风险事件保存到预警中心，并支持监护人联动。
6. 支持本地知识库持续增加新案例。
7. 支持测评集运行、指标统计、分模态分析和消融实验。
8. 使用本地模型时尽量减少原始数据离开用户设备的风险。

### 1.4 非目标范围

以下能力不属于当前版本承诺范围：

- 直接拦截手机电话、短信或其他应用的消息。
- 自动冻结银行卡、支付账户或资金。
- 自动拨打 110、96110 或其他公安电话。
- 替代国家反诈中心、公安机关、银行和通信运营商。
- 通过网页后台监听用户麦克风或通话。
- 在没有专用模型验证的情况下，确定某段声音或视频一定由 AI 合成。

## 2. 用户角色与使用场景

### 2.1 普通用户

普通用户可以输入或上传可疑信息，查看风险判断、证据和建议，并将高风险事件通知家人。

### 2.2 老年用户

老年用户重点关注冒充子女、养生保健、冒充客服、虚假投资、远程控制和公检法诈骗。界面需要支持大字号模式、清晰颜色和语音播报。

### 2.3 儿童或学生用户

儿童和学生重点关注游戏交易、账号买卖、追星应援、兼职刷单、虚假奖品和社交诱导。系统应支持家长或监护人联动。

### 2.4 青壮年用户

青壮年重点关注投资理财、虚假贷款、冒充领导、兼职刷单、网购退款、虚假征信和职业招聘。

### 2.5 监护人

监护人不负责模型分析，主要负责接收高风险通知、查看事件摘要、确认是否安全、表示需要帮助或补充处置意见。

### 2.6 管理与研发人员

研发人员通过知识库管理、测评中心和数据备份功能更新案例、检查模型效果和回归测试结果。

## 4. 详细功能需求

## 4.1 登录与本地会话

### 功能说明

提供简单的本地登录入口，用于进入系统和选择用户角色。当前版本不连接真实账号服务器。

### 功能要求

| 编号 | 要求 | 优先级 | 状态 |
|---|---|---:|---|
| LOGIN-01 | 输入手机号或本地用户名 | P0 | 已实现原型 |
| LOGIN-02 | 模拟验证码校验 | P0 | 已实现原型 |
| LOGIN-03 | 选择老人、儿童、青壮年或自定义角色 | P0 | 已实现 |
| LOGIN-04 | 登录状态写入 localStorage | P0 | 已实现 |
| LOGIN-05 | 退出登录并清除本地会话 | P0 | 已实现 |
| LOGIN-06 | 真实账号、密码和 JWT | P1 | 后续迭代 |

### 业务规则

- 登录页必须明确“当前为本地原型登录”。
- 模拟验证码只能用于演示，不能作为真实身份认证。
- 用户退出后，前端不得继续展示当前用户的个性化界面。

## 4.2 仪表盘

### 功能说明

仪表盘是用户进入系统后的首页，集中展示当前安全状态和最近风险事件。

### 页面内容

1. 今日安全评分。
2. 今日检测次数。
3. 已拦截或识别的风险数。
4. 待处理预警数。
5. 最近五条预警。
6. 快速检测入口。
7. 最近七日风险趋势图。
8. 当前模型和后端连接状态。

### 业务规则

- 低风险事件可以默认标记为已处理，但仍保留历史记录。
- 中风险和高风险事件默认进入待处理列表。
- 统计数据应区分本地演示数据和后端真实分析数据。
- 页面不得把“模型置信度”展示成经过校准的概率；当前结果应标识为分析结果或参考分数。

## 4.3 智能助手文本分析

### 输入

- 聊天记录。
- 短信内容。
- 邮件或社交平台消息。
- 用户补充说明。

### 约束

- 单次最多 10000 个字符。
- 支持中文、英文、数字、emoji 和换行。
- 前端限制长度，后端再次校验。
- 空文本禁止提交。

### 处理流程

```text
用户输入文本
    ↓
生成证据片段和字符位置
    ↓
查询官方案例与自建知识库
    ↓
读取用户角色和近期风险记忆
    ↓
调用 Ollama 风险模型
    ↓
校验模型 JSON、证据 ID 和案例 ID
    ↓
保存任务、分析结果和预警
```

### 输出字段

- 风险等级：low、medium、high。
- 评估状态：assessed 或 needs_review。
- 诈骗类型。
- 风险说明。
- 证据原文和字符起止位置。
- 引用案例。
- 防御建议。
- 使用的模型和知识库版本。
- 用户画像摘要。

### 异步任务要求

文本分析使用任务接口：

- `POST /api/analyses` 创建任务。
- `GET /api/analyses/{id}` 查询任务状态。
- 状态包括 queued、processing、completed、failed、interrupted。
- 服务重启时，processing 任务应标记为 interrupted，避免用户误以为仍在运行。

## 4.4 图片分析与 OCR

### 支持格式

- PNG。
- JPEG/JPG。
- WebP。

### 限制

- 单文件最大 10MB。
- 服务端必须检查文件类型和实际可解码性。
- 图片分析后不保存原始图片。
- 前端显示缩略图和分析结果。

### 处理流程

```text
上传图片
    ↓
校验文件和大小
    ↓
EXIF 方向修正与尺寸压缩
    ↓
视觉模型提取画面文字和风险线索
    ↓
结合补充说明和知识库
    ↓
生成风险判断、证据和建议
```

### 当前能力边界

当前使用本地视觉模型提取文字和语义线索，不承诺提供像素级 OCR 坐标框。需要精确坐标时，后续可接入 PaddleOCR，并将文字框保存为证据对象。

## 4.5 音频分析与录音

### 支持格式

- WAV。
- MP3。
- M4A。
- AAC。
- OGG。
- WebM。

### 限制

- 单文件最大 20MB。
- 最长 10 分钟。
- 浏览器录音最长 5 分钟。
- 录音需要用户主动点击并授权麦克风。
- 不允许后台监听。

### 处理流程

```text
上传或主动录音
    ↓
临时保存音频
    ↓
Faster-Whisper 转写
    ↓
保留时间戳 segments
    ↓
对转写文本进行 RAG 和诈骗风险分析
    ↓
删除临时音频文件
```

### 输出

- 转写文本。
- 分段起止时间。
- 检测语言。
- 音频时长。
- 诈骗风险等级。
- 话术证据。
- 防御建议。

### 明确边界

当前版本只分析语音内容，不判断声音是否由 AI 合成。页面必须显示“声音真伪未鉴定”。

---

## 4.6 视频分析

### 支持格式

- MP4。
- WebM。
- MOV。
- MKV。

### 限制

- 单文件最大 100MB。
- 最长 10 分钟。
- 服务端使用 PyAV 解码。
- 最多提取六个代表性关键帧。
- 原视频分析后删除，不持久化原始视频。

### 处理流程

```text
上传视频
    ↓
校验格式和大小
    ↓
PyAV 解码关键帧
    ↓
关键帧拼接为联系表
    ↓
视觉模型分析画面
    ↓
尝试提取音轨并转写
    ↓
RAG 检索与统一风险决策
```

### 输出

- 关键帧时间点。
- 画面识别文字和线索。
- 音轨转写文本。
- 风险等级和诈骗类型。
- 防御建议。
- AI 生成痕迹未鉴定说明。

## 4.7 多模态联合分析

### 功能说明

用户至少提交两种模态后，系统分别提取证据，再由风险模型统一判断，避免对同一内容重复计分。

### 支持组合

- 文本 + 图片。
- 文本 + 音频。
- 图片 + 音频。
- 文本 + 图片 + 音频。
- 视频作为独立的关键帧与音轨联合分析入口。

### 统一证据对象

每条证据应至少包括：

```json
{
  "id": "evidence-001",
  "modality": "text|image|audio|video",
  "excerpt": "证据摘录",
  "start": 0,
  "end": 12,
  "timestamp": 3.2,
  "source": "用户上传文件或文本"
}
```

模型只能引用系统提供的证据 ID，不得自行编造不存在的坐标、时间戳或案例编号。

## 4.8 风险识别与诈骗类型

系统首版覆盖至少十类诈骗：

1. 投资理财诈骗。
2. 兼职刷单诈骗。
3. AI 合成语音相关诱导。
4. 虚假征信诈骗。
5. 冒充公检法诈骗。
6. 虚假贷款诈骗。
7. 网络购物诈骗。
8. 游戏交易诈骗。
9. 冒充客服诈骗。
10. 婚恋交友诈骗。

### 风险等级规则

#### 低风险

- 普通社交内容。
- 未发现资金、身份或远程控制诱导。
- 提醒用户保持正常核实即可。

#### 中风险

- 出现可疑身份、链接、返利或陌生交易。
- 建议暂停操作并通过官方渠道核实。
- 可提醒监护人关注。

#### 高风险

- 明确要求转账、充值、提供验证码或进入所谓安全账户。
- 出现强制保密、恐吓、倒计时和冒充公检法等组合话术。
- 触发强提醒、浏览器通知和监护人联动入口。

### 个性化规则

用户角色和风险偏好只影响提醒方式、建议重点和案例推荐，不得覆盖真实证据，也不得因为用户是老人或儿童就凭空提高风险等级。

## 4.9 预警中心

### 功能

- 按风险等级筛选。
- 按诈骗类型筛选。
- 按日期范围筛选。
- 查看完整分析详情。
- 通知监护人。
- 发送 QQ 邮件。
- 标记已处理。
- 批量标记已处理。
- 查看通知和处置日志。

### 预警状态

```text
新建 → 待处理 → 已查看 → 已确认安全 / 请求帮助 / 已处置
```

通知投递状态与处置状态应分开记录。邮件发送成功只表示 SMTP 接受，不代表监护人已经阅读。

## 4.10 监护人联动与 QQ 邮件

### 监护人字段

- 姓名。
- 关系。
- 手机号。
- 邮箱。
- 是否默认通知。

### QQ 邮件要求

后端从环境变量读取：

```env
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=example@qq.com
SMTP_PASSWORD=QQ邮箱授权码
SMTP_FROM=example@qq.com
```

不得将授权码写入前端、数据库、日志或备份文件。

### 邮件内容

- 系统名称。
- 风险等级。
- 诈骗类型。
- 事件摘要。
- 防御建议。
- “请通过官方渠道核实信息，不要根据邮件直接转账”的安全提示。

### 失败处理

- 未配置 SMTP：返回配置提示。
- 邮箱格式错误：拒绝发送。
- 网络或 SMTP 失败：记录失败原因并提示用户。
- 不得显示“已发送”假状态。

- 高、中、低风险数量。
- 诈骗类型分布。

## 4.12 知识库与 RAG

### 知识库输入

- 手动粘贴文本。
- `.txt`。
- `.json`。
- `.csv`。

### 清洗规则

- 去除 HTML 标签。
- 压缩多余空白。
- 保留原文和清洗后的正文。
- 使用 SHA-256 去重。
- 完全重复内容拒绝重复入库。

### 索引规则

- 将文本切分为带少量重叠的片段。
- 使用 BGE-M3 生成向量。
- 向量和元数据保存到 SQLite。
- 优先进行语义检索，同时保留关键词检索兜底。
- 当前仅检索审核状态为 approved 的案例。

### 审核与版本

- 新案例可被禁用。
- 禁用案例不得参与检索。
- 支持创建知识版本快照。
- 支持发布版本。
- 支持从历史版本恢复并重建索引。

### 数据安全

- 知识库不能执行案例文本中的指令。
- 知识库内容只能作为参考证据。
- 模型输出必须经过 JSON 和引用 ID 校验。

## 4.13 小安数字人

### 当前版本

- SVG 形象。
- 待机、分析中、低风险、中风险、高风险、播报和错误状态。
- CSS 呼吸、眨眼、扫描和抖动动画。

### 后续升级

- Live2D 形象。
- 更自然的口型同步。
- TTS 服务。
- 情绪和动作状态。
- 3D 或视频数字人。

## 4.14 测评中心

### 当前数据集

- 至少 20 个案例。
- 黑白样本比例 1:1。
- 黑样本覆盖 10 类诈骗。
- 包含文本、图片和音频。

### 指标

- Accuracy。
- Precision。
- Recall。
- F1-score。
- False Positive Rate。
- TP、TN、FP、FN。
- 分模态准确率和 F1。
- 类型识别准确率。
- 平均响应时间。
- 失败数量。

### 测评分层

- development：开发集。
- validation：验证集。
- blind：盲测集。

### 消融实验

- 完整系统。
- 关闭 RAG。
- 关闭用户画像。

### 测试原则

- 最终盲测集不得用于反复调提示词。
- 训练/开发资料、验证集和最终盲测集应分离。
- 不同模态的同一原始案例不能冒充多个独立样本。
- 评测结果只能描述当前数据集表现，不代表现实世界准确率。

## 5. 数据需求

### 5.1 数据库核心表

当前 SQLite 至少包含：

- `jobs`：文本异步任务。
- `alerts`：分析预警和处置日志。
- `knowledge_cases`：知识案例。
- `knowledge_chunks`：向量检索片段。
- `knowledge_versions`：知识版本快照。
- `evaluation_runs`：测评任务和结果。
- `reports`：报告快照。

### 5.2 数据生命周期

1. 原始上传文件临时保存。
2. 分析完成后删除图片、音频和视频原文件。
3. 数据库存储分析摘要、证据、模型和知识库版本信息。
4. 用户可以删除自己的风险记忆。
5. 报告快照不随预警删除而变化。

### 5.3 备份

备份内容包括预警、知识案例、测评结果和报告，不包括模型密钥、SMTP 授权码和原始媒体文件。

## 6. 非功能需求

### 6.1 性能

- 文本和图片分析目标响应时间小于 10 秒，但本地模型首次加载可能超过该目标。
- 音频和视频允许较长处理时间，应显示进度或加载状态。
- 单次视频最大 100MB。
- 页面连续运行不应因单次模型失败而崩溃。

### 6.2 可用性

- 所有按钮均有禁用、加载、成功或失败反馈。
- 关键风险用文字、颜色和图标共同表达，不只依赖颜色。
- 支持大字号模式。
- 支持移动端布局。
- 支持减少动画模式。

### 6.3 安全

- API Key 和 SMTP 授权码只保存在后端环境变量。
- 前端不得接触模型密钥。
- 用户输入、案例文本和模型输出均视为数据，不执行其中的指令。
- 模型输出必须进行结构化校验。
- 失败响应不应暴露密钥、完整请求或内部堆栈。

### 6.4 可解释性

- 每个结论尽量引用输入证据。
- 引用案例必须来自实际检索结果。
- 没有案例支撑时明确显示“未引用相关案例”。
- 不把未经校准的模型分数称为概率。

## 9. 验收标准

### P0 核心验收

- 能登录并进入仪表盘。
- 能提交文本并完成真实本地模型分析。
- 能上传图片并得到视觉分析结果。
- 能上传音频并得到转写和风险结果。
- 能上传视频并得到关键帧和音轨分析。
- 能运行至少两种模态的联合分析。
- 结果能进入预警中心。
- 结果能生成安全报告。
- 知识案例能入库、检索和回滚。
- 测评中心能完成规则基线和模型评测。

### P1 交互验收

- 高风险时出现浏览器通知。
- 数字人切换到高风险状态。
- 数字人能够朗读建议。
- 监护人通知日志可查看。
- 配置 SMTP 后可以真实发送 QQ 邮件。
- 长期风险记忆可以查看和删除。

### P2 后续验收

- 真实账号和多用户隔离。
- HTTPS 公网部署。
- 声音 AI 深伪检测。
- 视频深度伪造检测。
- 更大规模测试集和压力测试。
- Live2D 或 3D 数字人。
