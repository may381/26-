# 安知·多模态反诈智能助手——项目板块与功能优先级规划

> 文档用途：明确项目详细方案中的功能层级、开发顺序、展示重点和后续迭代边界。
>
> 项目定位：面向老人、儿童、青壮年等群体，对用户主动提交的文本、图片、音频和视频内容进行诈骗风险分析，形成“输入—识别—预警—干预—反馈—进化”闭环。

## 1. 功能划分原则

项目功能分为三层：

1. **核心功能**：直接体现赛题要求和项目竞争力，缺少后将无法形成完整反诈闭环。
2. **辅助功能**：支撑核心功能稳定运行、数据管理和用户体验，但不作为主要创新点。
3. **增强功能**：用于后续比赛迭代、提升效果或完善产品形态，当前阶段可以逐步实现。

项目开发和答辩应始终围绕以下主线展开：

```text
可疑内容输入
    ↓
多模态证据提取
    ↓
诈骗风险识别与解释
    ↓
分级预警
    ↓
监护人联动与处置
    ↓
案例进入知识库并用于后续检索
```

## 2. 核心功能板块

### 2.1 多模态内容输入

**板块目标：** 让用户可以用最简单的方式提交正在遇到的可疑内容。

| 功能 | 优先级 | 说明 | 当前定位 |
|---|---|---|---|
| 文本输入 | P0 | 输入或粘贴短信、聊天记录、客服话术等内容 | 核心入口 |
| 图片上传 | P0 | 上传聊天截图、投资宣传图、转账页面等 | 核心入口 |
| 音频上传 | P0 | 上传语音消息或通话录音 | 核心入口 |
| 多模态联合提交 | P0 | 同时提交文本、图片、音频中的两种或以上 | 核心创新点 |
| 视频上传 | P1 | 提取视频关键帧和音轨后进行分析 | 增强型核心能力 |
| 浏览器录音 | P1 | 直接录制语音后提交 | 便捷入口 |

**页面规划：**

- 智能助手默认展示一个聊天式输入框。
- 图片、音频、视频以附件卡片或“添加证据”按钮呈现。
- 用户提交后，在同一会话中展示分析过程和结果。
- 不同时铺开多个大型表单，避免页面杂乱。

### 2.2 多模态证据提取

**板块目标：** 先把不同模态转换成统一、可引用的证据，再进行风险判断。

| 功能 | 优先级 | 实现方式 | 输出内容 |
|---|---|---|---|
| 文本预处理 | P0 | 清洗空白、特殊字符和重复内容 | 标准化文本 |
| 图片OCR | P0 | OCR提取截图中的文字 | OCR文本、图片来源 |
| 音频转写 | P0 | Faster-Whisper本地转写 | 转写文本、时间段 |
| 视频关键帧 | P1 | 定时抽帧或场景变化抽帧 | 关键图片证据 |
| 视频音轨转写 | P1 | 提取音轨后调用语音转写 | 音轨文本 |
| 证据对象统一 | P0 | 为证据分配ID并标记来源 | evidenceIds、摘录、来源 |

**重要原则：** 大模型负责选择和解释证据，不允许大模型凭空生成证据位置。

### 2.3 诈骗风险识别与解释

**板块目标：** 输出可理解、可核验的风险结论，而不只是给出“疑似诈骗”。

| 功能 | 优先级 | 输出要求 |
|---|---|---|
| 风险等级 | P0 | 低风险、中风险、高风险 |
| 诈骗类型 | P0 | 覆盖不少于10种典型诈骗类型 |
| 风险置信度 | P0 | 以百分比或等级展示 |
| 证据摘录 | P0 | 引用输入内容中的关键句或识别结果 |
| 风险说明 | P0 | 解释为什么存在风险 |
| 防御建议 | P0 | 给出可执行的核实、停止操作和求助建议 |
| 相似案例 | P0 | 从反诈知识库检索相关案例 |
| 个性化提醒 | P1 | 根据老人、儿童、学生、财会等角色调整表达方式 |

**必须覆盖的诈骗类型：**

1. 投资理财诈骗
2. 兼职刷单诈骗
3. 冒充公检法诈骗
4. 冒充客服诈骗
5. 虚假贷款诈骗
6. 虚假征信诈骗
7. 网络购物诈骗
8. 游戏交易诈骗
9. 婚恋交友诈骗
10. AI合成语音诈骗

### 2.4 分级预警与风险干预

**板块目标：** 根据风险等级采取不同强度的干预措施。

| 等级 | 页面表现 | 建议动作 |
|---|---|---|
| 低风险 | 绿色提示 | 保持警惕，核实身份 |
| 中风险 | 橙色警告 | 暂停操作，进行多渠道核实 |
| 高风险 | 红色强提醒 | 立即停止转账，联系家人，拨打110或96110 |

核心功能包括：

- 分析完成后自动生成预警记录。
- 预警包含风险等级、诈骗类型、证据、建议和时间。
- 支持查看详情、筛选、标记已处理和批量处理。
- 高风险事件进入监护人通知流程。

### 2.5 监护人联动闭环

**板块目标：** 在用户可能无法独立判断时，将风险传递给能够及时干预的第二个人。

| 功能 | 优先级 | 当前安排 |
|---|---|---|
| 监护人档案 | P0 | 姓名、关系、电话、邮箱、默认联系人 |
| 站内模拟通知 | P0 | 立即可用，用于演示完整流程 |
| 通知日志 | P0 | 记录通知时间、方式和状态 |
| 监护人确认页 | P0 | 支持已确认、核实中、确认风险等处置状态 |
| QQ邮箱通知 | P1 | 后端已经预留，获得SMTP授权码后启用 |
| 短信通知 | P2 | 后续可接入第三方短信服务 |

完整闭环：

```text
高风险分析结果
  → 创建预警
  → 通知监护人
  → 监护人查看事件
  → 监护人提交处置状态
  → 系统保存反馈记录
```

### 2.6 反诈知识库与RAG

**板块目标：** 让风险判断有案例依据，并使系统能够持续吸收新型诈骗案例。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 案例粘贴和文件上传 | P0 | 支持文本、TXT、JSON和CSV |
| 案例清洗 | P0 | 去除无关字符、HTML、空白和乱码 |
| 案例去重 | P0 | 使用哈希或内容相似度识别重复案例 |
| 分类保存 | P0 | 按诈骗类型管理案例 |
| RAG检索 | P0 | 分析时检索相似案例并引用 |
| 更新日志 | P1 | 记录入库时间、类型和数量 |
| 知识版本管理 | P2 | 支持版本发布和回滚 |
| 入库回归测试 | P2 | 验证知识更新是否导致误报或漏报增加 |

## 3. 辅助功能板块

### 3.1 用户与角色设置

- 模拟手机号验证码登录。
- 用户角色选择：老人、儿童、青壮年、自定义。
- 年龄、职业、性别等基本信息。
- 风险偏好设置。
- 大字号模式。
- 监护人资料管理。

该板块主要服务于个性化提醒和监护人联动，不作为诈骗判断的唯一依据。

### 3.2 仪表盘

- 今日安全评分。
- 今日检测次数。
- 风险拦截数量。
- 待处理预警数量。
- 最近5条预警。
- 最近7天风险趋势。
- 文本、图片、音频快速检测入口。

仪表盘用于总体展示和快速导航，不承载复杂分析操作。

### 3.3 安全报告

- 历史报告列表。
- 按时间范围生成报告。
- 风险趋势折线图。
- 诈骗类型分布图。
- 风险等级分布图。
- 风险说明和防御建议。
- 浏览器打印和导出。

报告板块主要用于阶段总结、用户复盘和比赛演示。

### 3.4 数字人“小安”

- 展示待机、分析中、低风险、中风险、高风险、错误等状态。
- 播报风险摘要和防御建议。
- 支持停止播报和静音。
- 在桌面端显示为紧凑状态栏，在移动端进一步收缩。

数字人是交互与展示功能，不参与风险计算，不应遮挡核心分析页面。

### 3.5 系统反馈与无障碍

- Toast操作反馈。
- 加载进度和错误提示。
- 大字号模式。
- 响应式布局。
- 减少动画模式。
- 文件格式、大小和输入长度提示。

## 4. 技术支撑板块

### 4.1 前端

- React 18 + TypeScript + Vite。
- Tailwind CSS及项目自定义主题样式。
- lucide-react图标。
- recharts图表。
- React Context管理用户设置、预警和通知状态。

### 4.2 后端

- FastAPI + Uvicorn。
- REST API提供分析、预警、知识库、报告和通知服务。
- SQLite保存结构化业务数据。
- `data/uploads`保存上传媒体。
- 环境变量保存模型与邮件配置。

### 4.3 AI能力

- Ollama本地大模型负责文本理解和结构化判断。
- Faster-Whisper负责音频转写。
- OCR能力负责图片文字提取。
- BGE-M3或兼容Embedding模型负责知识检索。
- 规则引擎用于模型失败时的基础兜底。

### 4.4 数据与隐私

- 默认本地处理用户上传内容。
- API密钥和邮箱授权码只保存在后端。
- 媒体文件不直接写入SQLite。
- 对外展示时使用合成或公开案例。
- 支持后续增加历史记录删除和媒体清理策略。

## 5. 测评与质量保障板块

### 5.1 标准测评集

- 不少于20个案例。
- 黑白样本比例为1:1。
- 黑样本覆盖不少于10类诈骗。
- 包含文本、图片和音频等不同模态。
- 开发集、回归集和最终测试集相互隔离。

### 5.2 核心指标

- Accuracy。
- Precision。
- Recall。
- F1-score。
- False Positive Rate。
- 平均响应时间。
- 各诈骗类型准确率。
- 各模态准确率。

### 5.3 稳定性验证

- 接口自动化测试。
- 模型异常与超时测试。
- 文件格式与大小边界测试。
- 连续运行测试。
- 并发和压力测试。
- 前端构建检查。

## 8. 推荐开发优先级

### 第一优先级：必须稳定

1. 文本、图片、音频输入。
2. OCR和音频转写。
3. 结构化风险分析。
4. 证据引用和防御建议。
5. 自动生成预警。
6. 预警查看和处置。

1. 监护人档案。

4. QQ邮箱通知配置。
5. 安全报告。
6. 测评中心。

### 第三优先级：提升演示和创新性

1. 数字人状态和语音播报。
2. 视频分析。
3. 个性化风险提醒。
4. 知识库版本和回归测试。
5. 声音鉴伪与深度伪造检测。

## 9. 答辩时应重点展示的功能

建议演示一条完整的高风险流程：

1. 选择老人角色。
2. 输入冒充公检法或刷单诈骗文本。
3. 同时上传聊天截图或语音。
4. 系统提取文本、OCR和语音证据。
5. 输出高风险等级、诈骗类型、证据和相似案例。
6. 自动生成预警。
7. 点击通知监护人。
8. 监护人查看详情并提交处置结果。
9. 在预警中心查看完整通知和处置日志。
10. 在报告或测评中心展示统计结果。

这条流程直接对应赛题要求的“诱导—识别—预警—监护人通知”全链路闭环。

## 10. 项目范围边界

本项目不替代国家反诈中心、公安机关或银行风控系统，不承诺：

- 自动冻结或追回资金。
- 自动报警或联系公安机关。
- 拦截其他应用的通话、短信或转账。
- 对声音或视频真伪作绝对判断。
- 将模型输出作为执法或司法结论。

系统发现高风险时，应明确建议用户停止转账、联系家人，并拨打110或96110核实。

## 11. 与国家反诈中心 App 的区别

### 11.1 对比结论

国家反诈中心 App 是面向全民的官方反诈工具，重点提供涉诈来电、短信、网址和应用风险预警、线索举报、身份核实、风险查询、报案助手和反诈宣传等能力。[官方及政务公开资料](https://legalinfo.moj.gov.cn/zhfxfzzx/fzzxyw/202506/t20250619_521225.html)显示，其定位是依托公安体系进行风险预警、线索汇聚和公众宣传。

本项目“安知”定位为**内容分析型反诈助手**：用户把正在看到的聊天记录、截图或语音提交给系统，系统解释其中的诈骗话术、证据和应对方法，并通过监护人联动形成家庭处置闭环。

因此，两个产品是互补关系，不是替代关系：

```text
国家反诈中心 App：通信/账号/网址风险防线
安知智能助手：聊天内容/截图/语音语义防线
公安机关和银行：报警、止付、冻结和案件处置防线
```

### 11.2 功能维度对比

| 对比维度 | 国家反诈中心 App | 安知智能助手 | 项目答辩表达 |
|---|---|---|---|
| 产品定位 | 官方全民反诈和预警工具 | 面向个人和家庭的内容分析助手 | 安知是对官方能力的场景补充 |
| 主要触发方式 | 系统或用户主动开启来电、短信等预警，也支持举报和风险查询 | 用户主动粘贴文本、上传截图、音频或视频 | 安知关注用户手里的具体内容 |
| 主要分析对象 | 涉诈电话、短信、网址、应用、账号等风险线索 | 聊天话术、宣传图片、语音转写和多模态证据 | 从“对象是否涉诈”扩展到“内容为什么可疑” |
| 工作层级 | 通信、账号和平台风险层 | 内容语义和交互解释层 | 两者处在不同防护层 |
| 文本分析 | 以预警、风险查询和线索举报为主 | 对整段对话进行语义理解、诈骗类型判断和证据摘录 | 安知更强调逐句解释 |
| 图片分析 | 可作为举报或线索材料提交 | OCR提取截图文字并参与风险判断 | 安知把截图变成可检索证据 |
| 音频分析 | 主要依赖电话预警及官方处置体系 | 音频转写后识别诱导话术，后续可扩展声音鉴伪 | 安知面向语音消息和录音材料 |
| 多模态融合 | 公开资料中重点是官方预警、举报、核验和宣传 | 文本、OCR、音频转写统一进入风险决策 | 多模态融合是本项目的比赛创新点 |
| 风险依据 | 公安涉诈风险数据、预警体系和用户举报 | 本地模型、规则、反诈知识库和相似案例 | 安知输出依据必须可解释、可追溯 |
| 结果形式 | 预警提示、风险查询、举报和报案入口 | 风险等级、诈骗类型、证据、相似案例、防御建议 | 安知更适合教学和用户理解 |
| 个性化 | 面向全民的统一官方服务 | 老人、儿童、青壮年、自定义角色和风险偏好 | 安知按用户理解能力调整提醒方式 |
| 监护人联动 | 主要面向本人预警、举报和报案 | 高风险后通知监护人，监护人可确认处置状态 | 安知增加“第二个人阻止转账”的环节 |
| 知识更新 | 官方统一发布权威宣传和风险信息 | 用户或管理员可上传案例、清洗、去重并进入RAG | 安知支持面向学校或社区的私有案例库 |
| 部署形态 | 官方移动 App，需要实名和系统权限 | 当前为响应式 Web，可在手机浏览器访问；后续可封装为 PWA、Android/iOS App 或小程序 | 安知先快速试验，再逐步移动端化 |
| 隐私边界 | 按官方 App 的实名、权限和隐私机制运行 | 项目设计为本地处理，密钥放后端，上传文件可清理 | 不把本地原型包装成官方服务 |
| 执法能力 | 可连接公安预警、举报和报案流程 | 不具备报警、止付、冻结或执法权限 | 发现高风险仍要拨打110或96110 |

### 11.3 安知真正应该强调的四个差异

#### 1. 从“风险对象”扩展到“风险内容”

国家反诈中心 App 重点解决“这个电话、网址、账号或应用是否存在风险”。安知解决的是“这段对话中哪句话在诱导我、为什么危险、下一步应该做什么”。

例如，陌生人使用一个暂未进入风险库的账号发送“点赞返现、先交保证金、下载指定 App”的消息时，安知可以从话术组合、资金要求和操作链路识别风险，并给出证据解释。

#### 2. 从单点提醒扩展到多模态证据融合

安知将聊天文字、截图中的OCR文字和语音转写结果统一为证据对象，再交给风险引擎判断。这样可以覆盖用户在微信、QQ、短视频评论区和语音消息中遇到的复杂场景。

#### 3. 从个人预警扩展到家庭处置闭环

安知不只显示风险等级，还支持通知监护人、查看受限事件详情、提交“已确认/核实中/确认风险”等处置状态，并保留通知日志。

#### 4. 从固定宣传扩展到可管理的私有知识库

学校、社区或团队可以把公开案例和本地高发案例加入知识库，经过清洗、去重和向量化后参与相似案例检索。该能力适合后续持续迭代，但不能宣称替代公安官方数据库。

### 11.4 必须承认的差距

答辩时应主动说明以下能力不属于本项目范围：

- 没有公安涉诈黑名单和官方账号库。
- 不能进行系统级来电或短信拦截。
- 不能确认对方真实身份或完成官方实名认证核验。
- 不能自动报警、冻结资金、追回损失或替代银行风控。
- 不能保证声学鉴伪或视频深度伪造识别百分之百准确。

推荐表述：

> 国家反诈中心 App 负责官方通信、账号和线索防护，安知负责用户主动提交内容的语义解释和家庭协同处置。安知发现高风险后，仍然建议用户停止操作，并通过110、96110或官方反诈渠道进行核实和求助。

## 12. 手机端部署规划

### 12.1 当前阶段：手机浏览器访问

当前 React Web 前端已经可以通过局域网地址在手机浏览器访问。电脑启动前端和后端后，手机与电脑连接同一 Wi-Fi，访问电脑局域网 IP 即可使用。

```text
电脑运行：前端 + FastAPI + Ollama + SQLite
手机访问：电脑局域网 IP:5174
模型处理：仍在电脑完成，手机只负责界面和上传内容
```

这种方式最适合当前开发和演示，不需要重新开发一套手机应用。

### 12.2 第二阶段：PWA 手机应用

可以给 Web 项目增加 PWA 配置，使用户能够在手机浏览器中“添加到主屏幕”，获得类似 App 的图标和全屏体验。

适合实现：

- 手机桌面图标。
- 响应式页面。
- 摄像头拍照上传。
- 麦克风录音上传。
- 离线缓存静态页面。

PWA 仍然需要后端服务提供模型分析，不能因为安装到手机桌面就自动变成本地模型 App。

### 12.3 第三阶段：封装为 Android/iOS 应用

如果比赛或后续产品需要安装包，可以选择：

| 方案 | 适合情况 | 改造成本 |
|---|---|---|
| Capacitor | 保留现有 React 页面，快速打包 Android/iOS | 较低 |
| Tauri Mobile | 希望获得更轻量的原生壳 | 中等 |
| React Native | 需要深度使用系统能力和原生交互 | 较高 |
| uni-app | 需要同时做小程序、H5和App | 中等 |

对于当前项目，建议优先选择 **PWA 或 Capacitor**，因为可以复用现有页面和接口。

### 12.4 手机端不能直接承担的内容

当前不建议把以下内容直接放进普通手机端运行：

- Ollama大模型。
- Faster-Whisper完整模型。
- Chroma或大型向量库。
- 复杂的视频抽帧和深度伪造模型。

原因是手机算力、内存、存储和系统权限不稳定。更合理的架构是：

```text
手机 App / 手机网页
        ↓ HTTPS API
后端服务（FastAPI）
        ↓
Ollama、OCR、Whisper、RAG、SQLite/PostgreSQL
```

### 12.5 推荐的移动端迭代顺序

1. 先完成桌面端核心闭环。
2. 做响应式适配，确保手机浏览器可以输入、拍照和录音。
3. 通过局域网 IP 进行手机联调。
4. 增加 PWA 图标和安装能力。
5. 使用 Capacitor 打包 Android 测试版。
6. 后续再考虑公网服务器、HTTPS、账号体系和正式发布。

因此，项目方案中的“Web 原型，可本地部署”并不意味着不能做手机端，而是表示当前先采用低成本的 Web 形态，后续可以平滑升级为手机网页、PWA、Android/iOS App 或小程序。
