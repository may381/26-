> 版本：V2.0｜2026-11-04
> 依据：《P2后端接口文档_v3.0》（57 个公开操作、49 条公开路径、8 个 Agent 内部操作；本地 8080 已可运行）
> 与 V1.6 的差别：V1.6 写"v3.0 仍是待确认草案"；V2.0 写"**P2 已实现并对前端开放，真实 A1/A2/A3 三方联调未完成**"。
> 一句话：**57 个公开接口全部归 P2；三个 Agent 只实现内部接口，各写各的领域逻辑。**

## 0. 本版改了什么

| # | V1.6 的写法 | V2.0 的写法 | 为什么改 |
|---|---|---|---|
| 1 | v3 是待确认草案，不能调用 | P2 v3 已实现并对前端开放，本地 8080 可跑，182 项测试通过；**A1/A2/A3 三方联调未完成** | 协议已变成实现，口径必须跟上 |

| 3 | 内部接口只写路径名 | 列出 **7 个已确认的内部接口 + 1 个待补**，并注明来源 | 避免拿"8 个操作"当已定契约去写代码 |
| 4 | 三个人各写模块 | 明确 **公开接口归 P2、内部接口归 Agent**，双方不重复实现 | 否则会出现两套会话、两套幂等 |

## 1. 先分清三个"调用"

| 调用 | 是什么 | 谁发起 | 现状 |
|---|---|---|---|
| 学校模型 qwen3.8-27b | 语言理解与生成引擎 | 三个 Agent 各自调用 | 可用（校园网） |
| P2 网关（8080） | 会话、任务、确认、附件、记忆、语音的唯一公开入口 | 前端 P1 | 已实现，对前端开放 |
| Agent 内部接口 | P2 → Agent、Agent → P2 的控制通道 | P2 与三个 Agent 互相调用 | 契约有、真实三方联调未完成 |

**学校模型不是 A1，P2 也不是 A1。** A1 是"接住需求、约束模型、决定能不能执行"的那段程序；P2 是"谁能调用、调完记在哪"的那道门。

## 2. 三个人分别负责什么

| 人员 | 主责 | 对外交付 | P2 给他什么 |
|---|---|---|---|
| **A1** | 总调度、多轮协调、结果整合；出行文旅、反诈骗 | 总智能体内部接口 + 旅游/反诈领域能力 | 任务单、确认对象、附件、记忆读取 |
| **A2** | 健康生活、家庭照护、求助协同、社区与志愿服务 | 协同模块的内部接口 + 领域逻辑 | 求助事件、通知记录、家属关系（只读授权内） |
| **A3** | 共享记忆机制、非遗文化、老人能力银行 | 记忆候选/审核接口 + 文化与能力银行模块 | 记忆读写通道、候选与审核的版本 |
| **P1** | 老人端/家属端/景区端页面 | 页面与交互 | 全部公开接口 |
| **P2** | 网关、任务与业务数据、鉴权、幂等 | 57 个公开接口 + 8 个内部操作 | — |

三条不能越的界：

- A1 决定"交给谁、先做什么"，**不能替 A2/A3 伪造办理结果**。
- A2/A3 **不实现公开接口**，也不自己开发会话与幂等；那是 P2 的。
- 长期记忆由 A3 主导机制，**P2 执行落库**，A1 负责准备确认；没有任何一方可以绕过确认直接写。

## 3. 学校模型怎么调用（不变）

| 配置 | 值 |
|---|---|
| 方法 | POST |
| 地址 | `http://10.138.50.151:8000/v1/chat/completions` |
| 模型 | `qwen3.8-27b` |

三个人各自调用、各自写提示词；共用的是"怎么发请求、怎么解析、失败怎么归一"，不是同一段提示词。

## 4. 调用链（v3 目标态）

```
老人
 │  ① 说话/发图
 ▼
P1 前端
 │  ② POST /api/v3/agent/messages   （带 Idempotency-Key、protocolVersion=3.0）
 ▼
P2 网关（8080）
 │  ③ 建任务、登记会话，返回 taskId —— HTTP 200 只代表"受理"
 │  ④ POST /internal/v3/messages    （任务单：目标、上下文、deadline、凭证）
 ▼
A1（或 A2/A3）
 │  ⑤ 理解 → 校验 → 决定自己办还是委派
 │  ⑥ 需要子任务：POST /internal/agent/v3/delegations
 │     需要确认：   POST /internal/agent/v3/actions + /confirmations
 ▼
P2：执行、登记、落库
 │  ⑦ 结果回传（dependencyResults / actionLedger）
 ▼
A1 整合 → ⑧ 返回 AgentResponse
 ▼
P2 持久化 → P1 轮询 GET /api/v3/agent/tasks/{id} 展示
```

四个必须记住的性质：

1. **异步**：POST 成功 ≠ 处理完。前端拿 `taskId` 轮询任务，A1 的回复在任务状态里。
2. **受理 ≠ 完成**：`WAITING_INPUT` 表示要追问、`WAITING_CONFIRMATION` 表示要逐项确认，都不是结果。
3. **幂等**：`Idempotency-Key` 由 P2 生成；Agent 不要为同一个动作另造一个键。
4. **确认不合并**：多个确认逐项处理，每项用自己的 `expectedVersion` 和独立幂等键；全部处理完才恢复 A1。

## 5. 内部接口清单（Agent 要实现的部分）

| # | 方向 | 路径 | 用途 | 来源 |
|---|---|---|---|---|
| 1 | P2 → Agent | `POST /internal/v3/messages` | 接任务，返回 AgentResponse | r3 已定义 |
| 2 | P2 → Agent | `GET /internal/v3/invocations/{id}` | 查调用收据（丢响应时用） | r3 已定义 |
| 3 | P2 → Agent | `POST /internal/v3/invocations/{id}/cancel` | 请求停止交付旧调用结果 | r3 已定义 |
| 4 | A1 → P2 | `POST /internal/agent/v3/delegations` | 委派子任务给 A2/A3 | r3 已定义 |
| 5 | Agent → P2 | `POST /internal/agent/v3/tasks/{id}/steps` | 登记步骤 | r3 已定义 |
| 6 | Agent → P2 | `POST /internal/agent/v3/actions` | 准备具体动作 | r3 已定义 |
| 7 | Agent → P2 | `POST /internal/agent/v3/confirmations` | 准备确认（只能 A1 做） | r3 已定义 |
| 8 | 待补 | —— | 官方文档说"8 个内部操作"，第 8 个未随文档提供 | 待《Agent内部接口文档_v3.0.md》 |

> **注意**：`POST /internal/agent/v3/delegations` 只有 A1 用；A2/A3 不主动向外委派，只通过第 5–6 项登记步骤和动作。
> 第 8 项没有文档前，**不要猜字段**，联调时按对方给的样例实现。

## 6. 57 个公开接口怎么分（全部归 P2）

| 链路 | 数量 | 谁在用 | 三个 Agent 的关系 |
|---|---|---|---|
| 链路一：游览主链路（档案、景点、路线、地图、游览、记录、分享） | 24 | 老人端 | **不实现**；A1 只在需要时读结果、做咨询 |
| 链路二：家属与求助（家属关系、通知、路线建议、留言、求助单） | 18 | 家属端/景区端 | **不实现**；A2 负责协同逻辑，数据走 P2 |
| 链路三：智能体对话（消息、任务、调用记录、确认、附件、记忆、语音） | 15 | 老人端 | **不实现**；这是 P2 对外的门面，Agent 在门后 |

一句话：**公开接口是 P2 的脸，内部接口是 Agent 的手。**

> 当前态与目标态要分开说：**当前** 8095 入口（页面 + 路由 + 会话）由 A1 负责人实现，是 P2 接入前的本地门面；**目标态** 这层职责归 P1/P2，A1 只保留内部接口。答辩时按"当前态"讲事实，按"目标态"讲分工，不要把两者说成同一件事。

## 7. A1 具体做什么

| 功能 | 具体内容 | 落在哪 |
|---|---|---|
| 需求理解 | 判断闲聊/咨询/办事，识别领域与缺失条件 | 学校模型 + 计划校验 |
| 任务拆分 | 输出 ASK/PLAN/REPLY；多步只展示不执行（当前） | 计划结构与单步白名单 |
| 多轮协调 | 补答接上一轮、保留限制、任务结束不串证据 | 会话历史 + 状态机 |
| 结果整合 | 统一 packet：回复、状态、执行轨迹、未执行声明 | packet 契约 |
| 出行文旅 | 旅游咨询、行程草案（程序排程）、地点/天气/票务 | 旅游域接口 |
| 反诈 | 文本/图片分析、风险分级、原文证据、分层建议 | 反诈域接口 |
| 委派与确认 | 通过 P2 登记步骤、准备动作与确认 | 内部接口 4–7 |

A1 的边界：**不伪造 A2/A3 的办理结果；不把模型文字当业务完成；不替用户报警、转账、订票。**

| 模块 | 做什么 | 和 P2 的关系 |

## 9. A3 具体做什么

| 模块 | 做什么 | 关键约束 |
|---|---|---|
| 候选提取 | 区分临时状态/长期偏好/经历，保留来源 | 候选不落库 |
| 去重与冲突 | 提出新增/合并/替换建议 | 建议不等于老人决定 |
| 相关检索 | 按任务返回少量有效记忆 | 只给 ID、版本、来源、时间；权限由 P2 查 |
| 生命周期 | 配合确认、纠正、删除、过期、撤权 | 删除后旧回复与恢复上下文失效 |
| 非遗文化 | 有来源的问答与课程候选 | 不编课程 |
| 能力银行 | 技能、意愿、供需匹配、贡献记录 | 审核与时长不由模型决定 |

**记忆流程**：各域提交候选 → A3 审核 → A1 准备确认 → P2 执行保存 → 三方按权限使用。**没有公开 POST 可以绕过这条链。**

## 10. 公共能力与归属

| 能力 | 主责 | 其他人怎么用 |
|---|---|---|
| 模型客户端 | A1 牵头 | 共用配置与解析，各自保留职责提示词 |

| 记忆落库 | **P2** | `memory.apply` 不开放给 Agent |
| 页面与确认展示 | P1 配合 A1 | 老人不需要选内部 Agent |

## 11. 任务单与结果单（按 r3）

**P2 → Agent（任务单）**

| 字段 | 含义 |
|---|---|
| 任务/会话/调用标识 | 归属与恢复关系，不由模型编 |
| 目标与协作领域 | 只查询、出建议，还是准备业务操作 |
| 必要上下文与附件引用 | 只给完成本任务所需的 |
| 凭证与截止时间 | 约束权限与时限 |

**Agent → P2（结果单）**

| 字段 | 含义 |
|---|---|
| 状态 | 完成 / 等输入 / 等确认 / 等依赖 / 失败（枚举以内部文档为准） |
| 回复 | 简短说明做了什么、还缺什么 |
| 结构化结果 | 按登记类型返回卡片数据 |
| 来源 | 真实工具、授权附件，不编 |
| 待确认操作 | 只引用 P2 已生成的确认 ID |
| 错误与局限 | 无资料、暂不可用、部分失败分别说明 |

**文档里明确出现过的状态**：`WAITING_INPUT`、`WAITING_CONFIRMATION`、`WAIT_DEPENDENCIES`、`EXECUTION_UNKNOWN`。完整枚举等《Agent内部接口文档》，**不要自己发明第三个状态名**。

## 12. 一个完整例子：找课程并找陪同（v3 版）

| 顺序 | 谁 | 做什么 |
|---|---|---|
| 1 | 老人 + P1 + P2 | "想学剪纸，别太远，希望有人陪" → 建任务，返回 taskId |
| 2 | P2 → A1 | 任务单：目标 + 上下文 |
| 3 | A1 | 缺地点 → 返回"等输入"，P2 登记问题，P1 展示追问 |
| 4 | 老人 | 补"长沙" → 带 continueTaskId 回答 |
| 5 | A1 | 拆两步 → 经 P2 委派文化查询给 A3 |
| 6 | A3 | 返回课程候选 + 来源 + 待核实项 |
| 7 | A1 | 整合推荐 → 老人选择 |
| 8 | A1 → P2 | 准备"陪同"动作与确认 |
| 9 | 老人 + P2 | 逐项确认 → P2 执行并落库 |
| 10 | A1 | 告知哪些已完成、哪些在等 |

**当前状态**：第 5–10 步都跑不通——A1 还没接入 P2，A2/A3 没有内部接口。演示时只讲结构，不演假调用。

## 13. 每人交什么 + 联调顺序

| 人员 | 交付 |
|---|---|
| A1 | 总调度内部接口、旅游与反诈模块、模型客户端、结果整合与恢复 |

1. 拿到《Agent内部接口文档》与 OpenAPI → 对齐字段，不写代码先对表。

3. 接调用收据与取消（丢响应、重启、迟到回复）。
4. 再加委派、步骤、动作、确认。
5. 最后接附件、记忆、语音（当前 mock）。

## 14. 口径红线

1. 不说"A1/A2/A3 三方联调完成"——文档自己写的是未完成。
2. 不说"P2 还是草案"——P2 已实现并对前端开放 57 个操作。
3. 不说"通知/报名/订票/语音已能用"——分别是外部能力、业务方、供应商、mock。
4. 不把内部接口当公开接口讲——公开的是 57 个，内部的是 8 个，两套不混。
5. 不编第 8 个内部操作的字段——没文档就不写。
