# 数据库建表字段建议 V1.0

日期：2026-10-31。供 P2 建表评审使用。
依据：项目总需求 XMind、P2 平台统一接口协议 v3.0、Agent 统一交互协议 v3.0、P2 后端接口文档及字段附录。

## 1. 先统一这些规则

本文是逻辑数据模型建议，不是已存在的数据库结构，也不是新增接口协议。P2已有同义表应复用，最终DDL由P2按数据库选型确定。未指明枚举、长度的新增字段是建议；协议已有约束优先。

| 项目 | 建议 |
|---|---|
| 命名 | 表和列使用snake_case；HTTP JSON继续使用协议camelCase，由程序映射 |
| 主键 | 新业务记录id使用UUID，逻辑类型UUID；数据库可用原生UUID或CHAR(36) |
| 外部标识 | user_id、actor_id、task_id等协议标识按不透明字符串处理，建议VARCHAR(128)，不要强制所有ID都是UUID；引用列与被引用列类型必须一致 |
| 时间 | created_at、updated_at统一UTC，精度毫秒；API输出ISO 8601。需要本地日期的行程另存timezone及date |
| 版本 | 可变业务对象增加version整数，初始1；UPDATE时检查旧版本，成功加1 |
| 公共列 | 除关联明细/不可变事件表外，默认包含id、created_at、updated_at；下文不重复。删除与保留规则按表设置，不统一机械软删除 |
| 空值 | 未知用NULL，不能用0表示未知台阶/距离，不用false表示未核实的无障碍条件。API不接受NULL的输入仍按协议拒绝 |
| 来源 | source/source_type与availability分开；availability为REAL/DEMO/UNAVAILABLE/NEEDS_VERIFICATION。业务来源按协议MOCK/OPEN_DATA/FIELD等登记值，不另造不兼容枚举 |
| JSON | 适合协议快照、卡片payload和工具参数；归属、状态、版本、外键、检索条件必须独立列，不能整个平台只存JSON |
| 权限 | P2检查归属与授权；Agent不直连数据库。模型原始推理不入库，密钥/任务凭证不写消息、工具参数或日志 |
| 精度 | 经纬度DECIMAL(10,7)，金额DECIMAL(18,2)，汇率DECIMAL(20,10)，时长单位明确 |
| 状态 | 分开任务状态、业务状态、确认状态、通知状态；枚举以正式Schema为准，不用一个status互相代替 |

类型说明：S(n)=VARCHAR(n)，TXT=TEXT，J=JSON，I=INTEGER，B=BOOLEAN，T=UTC时间。必填指落库完整记录；创建请求是否必填仍以API为准。

## 2. 共享档案与授权

### 2.1 elder_profile 老人档案

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| user_id | S(128) | 是 | 老人业务标识；唯一，不是profile.id |
| nickname | S(100) | 是 | 称呼 |
| age | I | 是 | 1～150，与当前接口保持一致 |
| residence | S(200) | 是 | 居住区域，不默认记录精确住址 |
| language | S(50) | 是 | 如普通话 |
| walk_speed | S(16) | 是 | SLOW/MEDIUM/FAST |
| walk_duration_min | I | 是 | 1～1440 |
| avoid_steps | B | 是 | 尽量避台阶的偏好，不是路线已核实 |
| interests | J | 是 | 数组，最多30项、每项100字符 |
| interaction_preference | S(16) | 是 | VOICE/TEXT |
| version | I | 是 | 乐观锁；长期记忆变更不能静默覆盖档案 |

### 2.2 emergency_contact 紧急联系人

profile_id外键必填；name S(100)、phone_ciphertext TXT、relation S(100)、sort_order I必填。电话按敏感数据加密，接口映射为phone；每份档案最多10人（事务内校验）。日志不输出电话明文。

### 2.3 family_relation 家属关系

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| user_id | S(128) | 是 | 所属老人，索引 |
| family_actor_id | S(128) | 否 | 实际绑定家属账号；演示绑定不等于正式手机号验证 |
| name / relation | S(100) | 是 | 姓名/关系 |
| phone_ciphertext | TXT | 是 | 加密存储电话 |
| status | S(24) | 是 | PENDING/ACTIVE/REVOKED |
| share_location / share_progress / share_alert / remote_planning | B | 是 | 四个独立开关，默认false |
| approved_at / revoked_at | T | 否 | 批准/撤销时间 |
| version | I | 是 | 授权版本 |

约束：同一老人同一家属账号有效绑定不可重复；撤销时权限全部关闭。绑定与权限变更保存审计，不以长期记忆代替授权。

### 2.4 consent_record 授权记录（建议补充）

user_id、actor_id S(128)，scope S(64)，purpose S(200)，resource_type S(64)、resource_id S(128)可空，state S(24)、version I，granted_at/expires_at/revoked_at T可空，evidence_ref S(128)可空。用于位置、健康、记忆、上传资料等授权，不替代family_relation四个权限。state枚举由P2统一登记。

## 3. Agent会话与任务底座

### 3.1 agent_conversation 会话

user_id S(128)必填；title S(200)可空；state S(24)必填；last_message_at T可空。索引(user_id,last_message_at,id)。会话状态为数据库建议，不能混用任务枚举。

### 3.2 agent_message 消息

conversation_id、user_id S(128)必填；task_id S(128)可空；role S(16)必填（user/assistant，内部事件另存）；text TXT必填；related_task_id S(128)可空；response_to J可空（原ownerTaskId/inputRequestId/version/selectedOptionId）；provenance_refs J必填默认[]。附件通过message_attachment关联，不把文件或凭证塞进正文。索引(conversation_id,created_at,id)。

### 3.3 agent_task 任务

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| user_id / conversation_id / message_id | S(128) | 是 | 归属及发起消息 |
| root_task_id | S(128) | 是 | 根任务；根记录指向自身 |
| parent_task_id | S(128) | 否 | 根任务为NULL |
| agent | S(16) | 是 | a1/a2/a3 |
| domain | S(64) | 否 | 已登记领域 |
| instruction | TXT | 是 | 用户约束和目标，不能包含凭证 |
| status | S(40) | 是 | 严格沿用协议任务状态机 |
| version / attempt / resume_generation | I | 是 | 对象版本、调用尝试、恢复代次；resume_generation为实现建议 |
| required | B | 是 | 子任务是否必须成功 |
| outcome | S(40) | 否 | 最终SUCCEEDED/PARTIALLY_SUCCEEDED/FAILED，与状态分开 |
| business_refs / read_set | J | 是 | 业务引用、记忆与授权依赖快照 |
| expires_at / deadline_at | T | 是 | 绝对有效期、本轮执行截止时间，不能混为同一个超时 |
| started_at / finished_at | T | 否 | 实际执行时间 |
| error_code | S(64) | 否 | 脱敏错误，不存上游原始异常正文 |

索引(user_id,conversation_id,status)、(parent_task_id,status)。任务创建、状态变化和恢复调度由事务保证。

### 3.4 task_dependency 依赖关系

parent_task_id、child_task_id S(128)必填；required B、created_at T必填。联合主键或唯一(parent_task_id,child_task_id)，禁止自身/环依赖。恢复事件唯一(parent_task_id,resume_generation)，避免先完成竞态造成漏恢复或重复调度。必要时另建调度outbox，不能仅靠内存回调。

### 3.5 agent_invocation 调用回执

invocation_id S(128)唯一；task_id、agent S必填；task_version、attempt I必填；request_digest S(64)必填；status S(40)必填；response_json J、error_code S(64)、error_retryable B可空；received_at/updated_at T必填；finished_at T可空；deadline_at T必填。状态用协议RECEIVED/RUNNING/FINISHED/FAILED/CANCEL_REQUESTED/CANCELLED。同invocationId不同规范化请求拒绝；同请求不得并行启动第二次。

P2与各Agent都需要自己的回执存储：P2保存调度记录，Agent保存收到及完成情况，不能仅建P2表就认为Agent已具备重放能力。

### 3.6 input_request 追问

input_request_id为UUID v4、全局唯一；owner_task_id/root_task_id/invocation_id S(128)必填；question TXT、required_fields J、options J、allow_free_text B、version I、state S(24)必填；content_digest S(64)必填；expires_at T必填；answered_message_id S(128)、answered_at T可空。

ID由产生问题的Agent程序生成；归属和version由P2维护。转呈子问题不新建记录。同ID不同内容/归属返回冲突。更新历史另存input_request_revision（question_id,version唯一，内容快照J）。

### 3.7 task_step / action / effect

| 表 | 必填业务列 | 可空列与约束 |
|---|---|---|
| task_step | task_id、plan_version I、client_step_key S(128)、tool S(128)、args J、prepare_key S(128)、state S(40) | 唯一(task_id,plan_version,client_step_key)；prepare_key唯一，不能交给模型 |
| action | task_id、step_id、tool、normalized_args J、args_digest S(64)、state、version | confirmation_id可空；step_id的动作准备唯一，执行入口由工具注册表限定 |
| effect | action_id、tool、business_type、business_id、business_version、execution_status、recorded_at T | provider_receipt可空且脱敏；唯一约束按工具幂等键确定；effect不可被Agent输出伪造 |

步骤登记请求request_key、request_digest和原响应必须持久化去重；建议放通用idempotency_record中，不能只在task_step里存最后一次值。失败/执行未知仍保留动作记录供对账。

### 3.8 confirmation 确认

user_id/task_id/action_id必填；operation S(128)、summary TXT、args_snapshot J、business_versions J、authorization_revision I、state S(40)、version I、expires_at T必填；decision_actor_id、decision_message_id、decided_at、executed_at可空。

确认状态遵循PENDING/APPROVED/EXECUTING/EXECUTED/EXECUTION_FAILED/EXECUTION_UNKNOWN/REJECTED/CANCELLED/EXPIRED/INVALIDATED。参数和授权快照冻结；变更范围需新动作/确认，不覆盖旧内容。一个动作不能通过不同入口执行两遍。

### 3.9 task_event / idempotency_record / invocation_cancel

| 表 | 字段与约束 |
|---|---|
| task_event | task_id、invocation_id、progress_seq I、event_type、phase、summary、created_at；唯一(invocation_id,progress_seq)，事件不能伪造业务完成 |
| idempotency_record | principal_id、operation、scope_id、key、request_digest、response_json、state、expires_at；唯一(principal_id,operation,scope_id,key)，保留期限按各接口规定，求助24小时；相同key不同正文拒绝 |
| invocation_cancel | cancel_request_id唯一、invocation_id、request_digest、response_json、created_at；重复返回同一控制响应，最终状态查回执 |

## 4. 共享长期记忆（A3主导，P2存储，三人共享）

| 表 | 主要字段 | 关键规则 |
|---|---|---|
| memory_candidate | user_id、category、content TXT、domains J、sensitivity、source_message_ids J、state、version、expires_at可空 | 临时情况不自动变成长期偏好；候选不等于生效记忆 |
| memory_review | candidate_id、candidate_version、reviewer_agent、recommendation、conflict_memory_refs J、proposed_domains J、needs_user_confirmation B、explanation TXT、version | recommendation为ADD/MERGE/REPLACE/KEEP/REJECT；审核不是写入 |
| memory_entry | user_id、category、content TXT、domains J、sensitivity、state、version、candidate_id、review_id、confirmation_id、effective_at、expires_at、deleted_at | 仅P2授权执行器写入；来源和本人确认可追溯；具体可空性按写入路径定义 |
| memory_source | memory_id、memory_version、source_type、source_id、source_version、created_at | 关联消息/业务反馈/附件等，验证所有者 |
| user_revision | user_id唯一、memory_revision I、authorization_revision I | 变更时事务递增；任务readSet与之对照 |
| memory_change_audit | user_id、memory_id、operation、old_version、new_version、actor_id、confirmation_id、created_at | 审计不永久保留已删除敏感原文；操作由实际执行产生 |

memory.change只引用已保存candidate/review的ID和版本，合并/替换带目标记忆版本；memory.apply不开放给Agent。向量索引若使用，增加memory_id/version索引引用及删除outbox；删除同时禁止检索、清理缓存、历史引用和恢复上下文，不能只删主表而留下可用副本。

## 5. 旅游业务

### 5.1 scenic / spot / facility / route / route_segment

| 表 | 字段 | 规则 |
|---|---|---|
| scenic | id、name、city、description可空、source、updated_at、verified_by可空 | 景区资料来源登记 |
| spot | scenic_id、external_id可空、name、description可空、description_available B、lat/lng可空、coordinate_system、source、verified_by可空 | 景点复合引用应带scenic_id；唯一(scenic_id,external_id)按实际ID方案确定 |
| facility | scenic_id、spot_id可空、name、type、lat/lng可空、coordinate_system、source、verified_by可空 | TOILET/BENCH/MEDICAL/EXIT/SERVICE_DESK；关联不等于最近或营业中 |
| route | scenic_id、name、source、verified_by可空、version | 推荐理由属于本次计算，不永久写成全用户共用recommended |
| route_spot | route_id、spot_id、sequence | 唯一(route_id,sequence)，保持顺序 |
| route_segment | route_id、sequence、from_spot_id、to_spot_id、steps可空I、slope可空DECIMAL、walk_min可空I、source、verified_by可空 | 未知不是0；若既有接口强制数字，P2需先补可空/核验约定，不能直接输出不兼容字段 |
| segment_rest_facility | segment_id、facility_id | 联合唯一；休息点资料与线路分开维护 |

P2景点原始坐标为WGS84；高德路径为GCJ-02，必须保存coordinate_system，转换产物不能覆盖原坐标。台阶/坡度/无障碍核实依据缺失时不得声称已核实。

### 5.2 trip 游览及 travel_feedback 反馈

| 表 | 字段 | 约束 |
|---|---|---|
| trip | user_id、route_id、route_snapshot J、status、started_at、finished_at可空、version | ACTIVE/FINISHED；同老人最多一条ACTIVE，事务或条件唯一索引保证 |
| travel_feedback | trip_id、user_id、effort、comfortable_walk_min可空、note可空、created_at | effort为EASY/COMFORTABLE/TIRED；唯一trip_id；幂等由请求记录控制 |
| trip_visit_evidence（待开发建议） | trip_id、spot_id、occurred_at、evidence_type、source_ref、coordinate_system可空 | 计划不等于实际到访；无采集时visitedSpotIds应未知，不从route_snapshot自动复制 |

游后记录可由trip+route_snapshot+feedback生成视图，避免再维护一份不一致记录。反馈不直接写档案或长期记忆，走候选审核确认流程。

### 5.3 itinerary_draft 行程草案与 itinerary 正式行程（协议后续范围）

| 表 | 字段 | 规则 |
|---|---|---|
| itinerary_draft | user_id、task_id、destination、start_date可空DATE、day_count I、timezone S(64)、preferences J、version、expires_at | 工作稿不是正式保存 |
| itinerary | user_id、source_draft_id、source_draft_version、confirmation_id、title、timezone、version、state | 本人确认后创建；不要直接把draft.saved翻true而无正式对象 |
| itinerary_item | draft_id或itinerary_id二选一、day_index、sequence、item_type、place_id可空、start_at/end_at可空、duration_min可空、time_basis、transport J可空、duration_basis、source_refs J、pending_checks J | VISIT/TRANSPORT/MEAL/REST/ACTIVITY；时间QUERIED/SUGGESTED/UNKNOWN；耗时QUERIED/ESTIMATED/UNKNOWN |
| itinerary_place / itinerary_leg | owner_type、owner_id、外部place_id、provider、坐标系、坐标、查询时间、来源快照、路线起终点及距离耗时可空 | 可按协议places/routes规范化；草案与正式行程分别版本化 |

日期、时区、来源、路线/餐休分别保存。UNKNOWN对应NULL。当前独立旅游原型中的文件草案需要迁移适配，不视为P2已建表或已上线。

### 5.4 guide_import / attachment / message_attachment

guide_import建议字段：user_id、task_id可空、source_kind（LINK/TEXT/IMAGE建议）、original_url可空、attachment_id可空、extracted_text可空、destination可空、places J、state、error_code可空、expires_at。正文和链接按最小期限保存，访问受控，抓取URL必须校验，不能直接信任模型生成链接。

attachment建议字段：user_id、purpose、mime_type、size_bytes、storage_key、content_hash、state、expires_at、deleted_at可空、version；purpose沿用fraud_analysis/travel_reference。storage_key不是公开永久URL，凭证不入库。message_attachment唯一(message_id,attachment_id)。READY才允许读取；默认有效期按协议24小时，可配置。原图不自动写长期记忆。

## 6. 求助、通知与业务关联

| 表 | 主要字段 | 规则 |
|---|---|---|
| help_event | user_id、trip_id可空、type、spot_id可空、scenic_id可空、lat/lng可空、coordinate_system可空、location_source可空、location_captured_at可空、location_note可空、business_status、assigned_actor_id可空、acknowledged_at/resolved_at可空、version | type SOS/LOST/UNWELL/GENERAL；OPEN→ACKNOWLEDGED→RESOLVED；spot引用与坐标二选一；无定位可文字说明。位置来源/采集时间为建议补充 |
| notification | help_event_id可空、recipient_actor_id、family_relation_id可空、type、delivery_mode、delivery_status、provider_message_id可空、sent_at/delivered_at可空、error_code可空 | 投递PENDING/SENT/DELIVERED/FAILED，与求助状态分开；MOCK不伪装真实送达 |
| notification_outbox（真实通知时） | notification_id、attempt、next_retry_at、state、last_error_code可空 | 先提交业务事务再投递；供应商回执去重；失败不重建求助 |

关系撤销后禁止查询历史缓存摘要。家属通知只返回当前有效关系可见的收件记录。

## 7. 扩展业务预留字段，不要求现在全部建表

以下均为建议模型，长度、状态、确认策略和API须由对应负责人和P2另行登记，不作为现有v3工具已开放的承诺。

| 业务/负责人 | 建议表 | 必要业务字段 |
|---|---|---|
| 反诈骗/A1 | fraud_analysis | user_id、task_id、attachment_refs、input_message_id、risk_level、findings J（含evidenceRefs/explanation）、recommended_actions J、limitations J、source_refs、expires_at；分析结论不是司法定性 |
| 文化课程/A3与普通活动/A2共用 | activity | type、provider_id、name、city、address可空、坐标及坐标系可空、start_at/end_at可空、timezone、capacity可空、fee_amount/currency可空、elderly_conditions可空、family_allowed可空、source、availability、verified_at可空、version |
| 活动场次 | activity_session | activity_id、start_at/end_at、timezone、capacity可空、state、version；有多场次才拆分，避免总课程与场次混淆 |
| 报名 | activity_registration | user_id、activity_session_id、confirmation_id、status、provider_registration_id可空、version；有效报名唯一，外部报名未接入不得标已成功 |
| 能力银行/A3 | capability_offer | user_id、skill、description、service_types J、service_area、available_time J、willingness、visibility、review_state、publish_confirmation_id可空、version；本人确认后发布 |
| 供需匹配 | capability_match | offer_id、request_ref、match_status、reason、source_refs；匹配不等于接单 |
| 志愿/A2 | service_request / service_assignment | request：发起人、服务类型、区域、期望时间、状态；assignment：request_id、provider_actor_id、接受/拒绝时间、状态、version |
| 服务时长/A2+A3共用 | contribution_ledger | assignment_id、user_id、duration_min、evidence_refs、reviewer_actor_id、review_status、credited_at可空；同服务贡献唯一，不在两处重复计入 |
| 照护/A2 | care_task | elder_user_id、initiator_actor_id、assignee_actor_id、type、description、scheduled_at、timezone、confirmation_id、status、version；多人分工另建care_assignment |
| 健康/A2 | health_record / reminder | 资料：user_id、category、本人提供内容、来源、授权及可见范围；提醒：user_id、schedule、timezone、channel、enabled、next_fire_at、cancelled_at；不保存模型猜测的诊断 |
| 学习/A3 | learning_record / learning_work | user_id、activity_id、progress、completed_at可空；作品：storage_key、mime_type、visibility、consent_ref、deleted_at可空 |
| 汇率/A1可选 | exchange_rate_cache | base_currency、quote_currency、rate、provider、rate_date、retrieved_at、expires_at；唯一(provider,base_currency,quote_currency,rate_date)，注明参考价而非交易承诺 |

机构资源来源由机构录入/合作资料/公开资料提供；能力银行来自本人确认的技能与意愿。模型不能编造真实机构、课程、技能或服务结果。原始模拟数据统一标MOCK/DEMO，不与生产资源混写。

## 8. P2建表时需要落实的约束

1. 归属链完整：消息、任务、附件、确认和业务对象可追溯至同一老人；越权校验不能只看ID存在。
2. 同invocation不重复执行；同动作不从tools/delegations等不同入口执行两次；幂等唯一键采用固定规范化算法，不包含会轮换的凭证。
3. 追问新ID全局唯一；P2分配问题版本；用户答案只恢复原问题owner任务。
4. 依赖登记后立即检查子任务状态，事务内落恢复事件；并发只调度一次父恢复。
5. 确认决定、执行账本、outbox在可恢复事务边界落库；未知结果保留并对账，不轻易重试外部副作用。
6. memory/authorization revision变更后让相关readSet失效，删除与撤权覆盖缓存、历史和恢复上下文。
7. 演示身份头只用于隔离的测试环境；不能把X-Mock-Actor头作为上线登录认证。
8. 日志与样例不含密钥、真实电话、健康原文；消息、附件、回执和审计保留期限分别配置。模型原始推理不保存。

## 9. 哪些先复用、哪些新增

| 类别 | 建议 |
|---|---|
| 现有业务可评估复用 | 档案、家属关系、景区景点路线、游览、求助通知、游后反馈；先核对P2现有实体和迁移脚本，不能据此认定已经存在同名表 |
| v3首批新增/改造 | 会话消息、任务依赖、调用回执、问题版本、步骤动作、确认、执行账本、幂等、共享记忆 |
| 旅游后续新增 | 正式多日行程、实际进度证据、攻略导入持久化；与现有文件草案迁移对应 |
| 扩展业务 | 活动课程、能力银行、志愿时长、照护、健康、作品和反诈记录，按工具实际开放情况建表 |

请P2按已有表映射本文逻辑实体，确定最终表名、数据库类型、索引、状态枚举和保留期限。接口字段不因数据库命名改变；新增业务字段先更新字段注册与Schema，再提供给Agent使用。
