# 时光链 A1：实现原理与逐环节讲解

本文件对应当前代码审计，不等于所有服务已完成生产部署。产品演示前需运行真实接口联调。

## 1. 先记住这句话
我们做的是面向老人的统一服务入口。学校大模型负责理解和推理，领域智能体负责专业流程，工具接口提供地点和业务数据，程序负责校验与状态管理。老人不需要知道该找哪个模块。

## 2. 它不是一个模型套多个页面
学校 qwen3.8-27b 是共享的推理引擎。A1 是我们编写的协调程序，包含提示词、任务结构、校验器、多轮上下文、领域客户端和状态机。A2、A3也是各自的业务程序，而不是三台不同模型。
学校模型不会自动知道实时票价、定位、家属权限或用户档案。这些必须来自真实接口和授权。

## 3. 从输入到回答：你应逐步讲出
1. 浏览器输入：A1new/app.js 收集文字或图片。语音识别的可用性取决于所接语音通道；不能把系统浏览器语音能力说成自研方言模型。
2. 本机入口：A1new/server.py 接收 /api/message，检查来源、输入大小和会话。会话内存保存，闲置会过期，服务重启会清空。
3. 综合分流：a1-orchestrator/domain_chat.py 调用 Conversation.turn；明确选中领域时可绕过总规划，直接进领域服务。
4. 模型请求：a1-orchestrator/a1.py 的 ask_model 用 HTTP POST 调用学校 /v1/chat/completions。messages 包含系统规则、本轮会话历史和用户输入。temperature=0.1，stream=false，关闭内部思考输出。
5. 模型返回结构化计划：decision 为 ASK/PLAN/REPLY；steps 包含 agent、domain、goal、dependsOn。不是让模型随意返回可执行代码。
6. 校验：检查 JSON、合法领域、步骤编号、前置依赖、位置证据。地点只能引用用户原文，不能从模型想象得出。
7. 执行范围：当前仅接受单步 A1 旅游或反诈。多步骤和 A2/A3 委派仍待正式 P2 网关，不伪造执行成功。
8. 领域调用：local_domains.py 只请求固定本机后端。旅游8091，反诈8000。模型生成的 goal 不替代用户原文证据。
9. 结果处理：旅游同步返回；反诈可先返回任务受理，再轮询状态。任务受理不等于完成分析。
10. 展示：旅游地图和时间轴、反诈风险证据卡；新增 executionTrace 展示程序真实经过的阶段，不展示或编造内部思维链。

## 4. 为什么需要工具
高德提供地点ID、坐标、地址、照片、路线耗时和部分公共交通结构。页面地图 SDK 提供缩放拖动。服务器代理承担安全配置转发。
票价参考不是实时可购买报价，路线接口没有返回余票时不能说有票。售票供应商权限没有获得时不承诺出票。

## 5. 旅游流程的真实边界
准备计划按钮目前通过前端收集目的地、日期、交通和体力偏好，调用 Java TravelDraftApi，再由 TripPlanner 按地点坐标邻近关系分组、查询交通、插入游玩和休息建议。这里不是学校模型生成整份旅游方案。
学校模型用于总入口理解、旅游咨询及相关识别等能力；不要把所有时间轴称为大模型实时思考结果。
减少台阶目前包含基于地点名称的优先级调整，不是已核实的无障碍路径；实际坡度、座椅、开放时间未验证时需明确标注。

## 6. 会话与记忆
本次聊天上下文是短期记忆，保存在进程内；计划补充信息部分保存在浏览器 localStorage。A3共享长期记忆和P2权限还没有完整接通。
不能说我们已经实现跨设备永久记忆、医疗档案闭环或真实家属通知。

## 7. 失败为什么是产品能力
模型超时、结果截断、JSON无效、领域服务未启动都要提示失败；保留原文与待处理任务引用。反诈提交结果不确定时不要重复创建任务。没有收到成功响应不得声称已通知、冻结、报名或预订。

## 8. 你现场可以打开哪些代码
- a1-orchestrator/a1.py：系统提示词、模型请求、JSON校验、会话历史。
- a1-orchestrator/domain_chat.py：协调状态、原文传递、任务分流与执行记录。
- a1-orchestrator/local_domains.py：受控HTTP客户端、错误处理、幂等引用。
- A1new/server.py：统一入口、会话锁、工具路由、地图安全代理。
- a1-guide/server/src/main/java/cn/yinling/guide/TravelDraftApi.java：真实草案API。
- a1-guide/server/src/main/java/cn/yinling/guide/TripPlanner.java：地点分组和时间排程。
- 外包A30/anti-fraud/backend/app/main.py：案例检索、模型分析与结构校验。
- A1new/fraud-ui.js：证据卡和异步轮询。

## 9. 一次练习
输入“想出去玩，少走路”，观察追问；补充城市后观察分流。再提交明确的模拟诈骗原文，观察反诈任务受理、轮询和证据卡。最后关闭一个后端，观察明确失败，证明页面没有偷偷编造成功。
讲解时先说用户问题，再说调用链，再展示证据。不要只展示漂亮结果截图。
