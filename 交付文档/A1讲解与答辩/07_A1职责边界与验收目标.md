# A1 职责边界与验收目标

> 写给只负责 A1 的你。
> 目的：把"我该做到什么程度"和"我该懂什么"说死，避免两个极端——什么都想管、或者不知道管到哪。
> 配套：《05_智能体开发教程》讲方法，这份讲**范围和验收**。

---

## 0. 一句话结论

在这个项目里，A1 不是"三个智能体之一"，而是**三件事绑在一个人身上**：

> **唯一入口（P1 与 A1 的交界） + 协调者（A1 的本体） + 两个业务域（旅游、反诈）**

答辩时最容易犯的错，是把这三层混成一句"我做了总智能体"。评委一听就会追问"那你到底是前端还是后端"。**先分层，再讲任何一层。**

---

## 1. 你的边界

### 1.1 三层，各归各

| 层 | 你负责的 | 主要文件 | 一句话判据 |
|---|---|---|---|
| **入口层** | 统一输入、会话、图片、语音转写、历史、状态提示 | `A1new/index.html`、`app.js`、`server.py` | 用户**只面对一个输入框**，不用选 Agent |
| **协调层** | 理解、追问、分流、校验、状态机、执行记录 | `a1-orchestrator/a1.py`、`domain_chat.py` | 模型说的**每一步都要过程序** |
| **领域层** | 旅游咨询、反诈分析、票务查询 | 8091 / 8000 / `tickets.py` + 前端卡片 | 结果**从真实接口来**，不是模型编的 |

三层的关系只有一句话：**入口负责"接住"，协调负责"决定"，领域负责"办事"。**

### 1.2 不归你，别揽

| 不归你 | 归谁 | 你只需要做到 |
|---|---|---|
| 健康、照护、社区、志愿、文化、能力 | A2 / A3 | 认得这些领域、明确说"未接入"，不假装能办 |
| 任务网关、身份鉴权、持久存储、共享记忆 | P2 | 对得上报文格式，不自己造一套 |
| 页面视觉规范、适老化交互设计 | P1 | 按规范实现，不自己发明 |
| 地图数据、路线算法、学校模型训练 | 高德 / 学校 | 会用、会讲边界，不宣称自研 |
| 12306 / 航司的订票、锁座、支付 | 供应商 | 只读查询，**明说不订票** |

### 1.3 你必须守住的四个契约（背下来）

| 契约 | 形状 | 违反的后果 |
|---|---|---|
| **对前端** | `{reply, state, domainResult, executionTrace, notificationExecuted:false, sharedMemoryWritten:false}` | 前端拿到看不懂的东西，只能显示"出错了" |
| **对领域** | 旅游 `POST /api/agent/messages`；反诈 `POST /api/analyses` + `Idempotency-Key` | 重复下单、丢结果 |
| **对模型** | `messages` + 只要 JSON + `finish_reason=stop` 才收 | 半截计划被当成真计划执行 |
| **对 P2（将来）** | r3 形状的 invocation / response + 凭证 + deadline | 接不上网关，跨 Agent 永远停在 PPT |

> 【会讲】我不是"想做多大就做多大"，我是**四个契约的交汇点**：前端怎么问我、我怎么问模型、我怎么派活、将来怎么接网关。这四件事任何一件走样，整条链就断。

## 2. 目标：分三层，别一锅端

### 2.1 底线（不满足就不算 A1 做完）

每条后面都写了**怎么验**，验不过就是没做到。

| # | 目标 | 验收动作（当场做） |
|---|---|---|
| 1 | 一个入口接三类输入：文字、图片、（可选）语音转写 | 分别发文字、传 PNG、点麦克风，各有明确结果或明确失败 |
| 2 | 综合模式必须三选一：ASK / PLAN / REPLY，**不能既不问也不答** | 输入"想出去玩"→ 必须追问；输入"你好"→ 必须直接回；输入具体诈骗原文 → 必须出计划 |
| 3 | 执行白名单：只跑已接通的域，未接通的明确拒绝 | 输入"帮我挂个号"→ 必须说"未接入"，**不能假装查了** |
| 4 | 模型输出过五层校验；地点必须来自原文 | 断网/改模型输出→ 必须报"计划解析失败"，不是"好的我帮您安排" |
| 5 | 领域调用传**原文**、带超时、带幂等 | 提交诈骗原文 → 8000 收到的应是原文；重复提交 → 复用同一幂等键 |
| 6 | 失败必须说清三件事：哪一步、为什么、下一步 | 关掉 8000 → 页面必须出现具体错误原因，而不是"网络异常" |
| 7 | 会话有边界且如实说明 | 1 小时闲置清理、单会话串行（并发返回 409）、50 会话上限、重启即清空 |

**底线只有一句话**：**在任何输入、任何故障下，系统都必须给出一个"诚实的结局"。**

### 2.2 合格（答辩能过）

| # | 目标 | 效果 |
|---|---|---|
| 8 | `executionTrace` 五阶段可展开，且与真实调用一致 | 评委点开"查看实际调用过程"，看到接收→规划→校验→委派→结果，有耗时、有状态 |
| 9 | 两种入口的差别讲得清 | 综合=模型分流；直接选"出行/防诈"=跳过模型直连领域，trace 第一段是 `selection` |
| 10 | 旅游链路：真实地点/交通 → 程序排程 → 时间轴/地图 | 能指出"这段是地图估算（AMAP_ESTIMATE），不是模型想的" |
| 11 | 反诈链路：受理 → 轮询 → 证据卡 → 分层建议 | 能指出 `evidence` 对应原文哪一句；`needs_review` 会显示"信息不足" |
| 12 | 至少 3 条负向测试可复现 | 关 8000、超长输入、非法 topic，各有确定行为 |
| 13 | 数字口径统一 | 说得出每个数字对应哪个测试文件、哪条命令 |

### 2.3 加分（评委眼前一亮）

| # | 目标 | 为什么加分 |
|---|---|---|
| 14 | 把"不确定"做成状态：`SUBMISSION_UNCERTAIN` + `/retry` 复用幂等键 | 大多数队伍没想过"超时后对方到底收没收到" |
| 15 | 票务只读：不锁票、不订票、缺价不当 0 元、无凭证明确失败 | 证明你想过合规和"不假装" |
| 16 | 状态自检页：端口可达 ≠ 模型可用（`modelVerified:false`） | 主动拆穿"绿点=能用"的假象 |
| 17 | 故意演示失败 | 成功可能是演的，失败演不出来 |
| 18 | 被问"加个新域"能说出改哪几处、卡在哪 | 证明你懂结构，不是背稿 |

### 2.4 用户视角的目标（一句话）

> 老人**一次输入**就有明确结局；出游从填表到看到时间轴不超过 4 步；可疑信息从粘贴到 3 分钟内**要么出结果、要么明确告知"仍在等待/可手动查询"**；任何失败**一次操作**就能看到原因和下一步。

这四句比"提升体验"有用，因为它可测。

### 3.2 六个要收口的地方（按风险排序）

**① 数字口径对不上（高风险，最容易被当场问住）**
验收单写"A1 51 项"，旧文档写"协调器 58 项"，实测是：**协调器 170 个用例（18 个文件）、统一入口 17 个用例（server 8 + 票务 9）**。三个历史数字指的不是同一堆测试。
→ 统一口径为实测值，做一张对照表：`数字 | 命令 | 对应文件`，答辩只念这张表；被追问就当场跑一遍。

**② "无 iframe"的说法不严谨（中风险）**
主流程确实是原生弹窗，但 `tourism-entry.js` 里的"旅游完整功能"仍然是 iframe 打开 `/tourism/index.html`。
→ 要么改口径："主流程全原生，完整工作区是嵌入的独立页面"；要么把这个入口替换掉。**别在答辩时说"我们完全没有 iframe"，评委一按就露。**

**③ 直接选域后的状态可能挡住下一句话（中风险，设计问题）**
直接点"防诈"提交后 `state=WAIT_RESULT`；这时用户切回综合问别的，会被"已有反诈任务，请先 /status"挡住。
→ 想清楚这是**有意的一任务一对话**，还是 bug。是设计就写进说明；是 bug 就加"切换领域时提示可 /new"。答辩被问到，答"我们故意不让两个任务并行，避免证据串台"。

**④ 票务的合规与凭据（中风险）**
Amadeus 密钥走环境变量是对的；但要确认：不进日志、不进代码、不进交付包；12306 只读接口可能限流/变更，页面要有"以官网为准"。
→ 交付前跑一遍 `grep -ri "AMADEUS\|secret" A1new`，确认没有硬编码。

**⑤ 前端三个大文件讲不清（低风险，但影响印象）**
`rich-replies.js` 36KB、`ticket-ui.js` 29KB、`mobile-app.css` 40KB，评委问"这堆是干嘛的"你答不上就掉分。
→ 记住一句话分工：**`app.js` 管流程，`*-ui.js` 管弹窗，`rich-replies.js` 管"长得好看"**。只讲这一句就够。

**⑥ 自检页的措辞（低风险）**
`/api/health` 返回 `modelVerified:false` 很诚实，但要主动解释："这是存活检查，不是模型健康检查。"

## 4. 知识地图：你该懂到什么程度

### A 类：必须能当场答（10 个，30 秒内）

| 问题 | 答案骨架 |
|---|---|
| 1. 综合入口和直接选域，差在哪？ | 综合先调学校模型出 ASK/PLAN/REPLY，再校验再派活；直接选域跳过模型，程序直接请求 8091/8000，trace 首段是 `selection` |
| 2. 三个 decision 什么时候出现？ | 缺必要条件→ASK；问候/常识→REPLY；要办事→PLAN |
| 3. 地点为什么必须校验？ | 地点是后续所有查询的入参，模型编一个城市，后面全错；属于证据来源问题 |
| 4. trace 有哪几段？各证明什么？ | 接收/规划/校验/委派/结果；证明程序真的走了这几步，不证明模型想得对 |
| 5. 为什么受理不等于完成？ | 反诈是异步任务，受理只代表"收到"，结果要轮询；把受理说成完成就是编 |
| 6. 幂等键什么时候生成？为什么必须复用？ | 首次提交前生成；重试复用才能被对方去重，否则可能两个任务、两次通知 |
| 7. 三个服务端口和职责？ | 8095 统一入口；8091 旅游；8000 反诈；学校模型在校内地址 |
| 8. 哪条链路不经过大模型？ | "准备计划"按钮：表单→Java TravelDraftApi→TripPlanner（高德数据+程序排程） |
| 9. 失败时页面显示什么？ | 具体原因 + 已做到哪一步 + 下一步（重试/查询原任务/检查服务） |
| 10. 你的证据在哪？ | `A1new/qa/*.json`（真实模型/真实接口响应）、`qa/学校模型联调记录.md` |

### B 类：应该理解原理（8 个，能画图/举例）

1. **会话与并发**：cookie 认人、每会话一把锁、忙则 409、闲置 1 小时清、上限 50。
2. **超时预算**：前端 260s、模型 90s、领域 100s（图片 220s）、反诈模型 180s——**逐层放大，不是随便设的**。
3. **结构化输出**：为什么先定 JSON 骨架，再写提示词。
4. **校验分层**：结构→取值→关系→来源→业务。
5. **状态机**：READY / WAIT_RESULT / SUBMISSION_UNCERTAIN / COMPLETE / FAILED 的合法转移。
6. **上下文控制**：2000 字、12 轮、累计 10000 字。
7. **错误契约**：502 响应也带 `executionTrace` 和 `submissionUncertain`，前端才能画"失败到哪一步"。
8. **只读外部数据**：12306/Amadeus 只查不订，缺数据就明说，不补 0。

### C 类：可以不懂，但别装懂（5 个）

- 学校模型怎么训练、怎么部署、多少参数
- 高德底图和路径规划的内部算法
- 12306 接口的稳定性、合规边界、是否会封
- 语音识别（浏览器 Web Speech，不是自研方言模型）
- 反诈的"准确率"（现在没有，别报数）

> 被问到就说："这块不是我做的/我们没有评测数据，我不能给结论。" **这句话不丢分，编数字才丢分。**

### D 类：必须会操作（6 个）

| # | 操作 | 要点 |
|---|---|---|
| 1 | 一键启动 / 单独启动 / 查状态 | `A1new/统一启动/一键启动全部.cmd`；端口通 ≠ 模型可用 |
| 2 | 跑后端单测 | 在 `A1new` 下 `python -m unittest test_server -v`、`test_tickets -v` |
| 3 | 跑浏览器校验 | 需要先开 Edge 远程调试端口 9230 并打开 8095，再 `node test-xxx.cjs`；**它拦的是前端 fetch，不证明后端** |
| 4 | 打开证据 | `qa/coordinator-fraud-live.json` 等，能指出"这是哪次、哪个模型、什么结果" |
| 5 | 改一条规则复测 | 改 `SYSTEM` 一句话 → 重跑同样的输入 → 看 decision 变没变 |
| 6 | 关服务演示失败 | 关 8000 → 再发一次 → 讲"宁可报错也不编" |
