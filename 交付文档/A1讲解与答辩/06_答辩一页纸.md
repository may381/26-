# A1 答辩一页纸

> 打印一页，答辩前 10 分钟只看这张。详细内容见《05_智能体开发教程》。

## 一句话定位

> 我们给老人做一个统一入口：说一句话，它自己判断该找旅游还是该核对可疑信息，然后把结果连同依据一起摆在老人面前——能办的说办到哪一步，办不了的说办不了。

## 30 秒稿

> 老人出门和使用手机有两类困难：不会规划、不会判断信息真假。我们做了一个统一对话入口，背后是学校大模型加真实地图数据，再加一层程序校验。老人说一句话，自动分流到旅游规划或风险核对，并把依据、来源、没做到的事都摆出来。现在跑通的是本机原型和部分真实接口，下一步是社区试点和误判评估。

## 五零件（讲架构就按这个顺序）

| 零件 | 一句话 | 文件 |
|---|---|---|
| 角色规则 | 告诉模型它是总调度，只规划不执行 | `a1.py` 的 `SYSTEM` |
| 输入契约 | 挡空、挡超长、挡无限对话 | `Conversation.turn` |
| 决策+校验 | 模型出 ASK/PLAN/REPLY，程序过五层安检 | `validate_plan` / `enforce_location` |
| 执行器 | 只认单步 a1 旅游/反诈，地址写死本机 | `domain_chat` / `local_domains` |
| 状态+记录 | 受理≠完成，失败要显式 | `state` / `executionTrace` |

## 四问法（每展示一个结果都答一遍）

1. 输入是什么？
2. 调用了谁？
3. 依据从哪来？
4. 哪些操作**没有**执行？

## 三张要能徒手画的图

```
① 主链路：老人 → 浏览器 → Python(8095) → 学校模型 → 程序校验 → 8091旅游/8000反诈 → 结果+依据
② 非模型链路：填表 → Java TravelDraftApi → TripPlanner(高德+排程) → 时间轴/地图   ← 这条不是大模型排的
③ 状态机：READY → WAIT_RESULT → COMPLETE/FAILED；出错不知收没收到 → SUBMISSION_UNCERTAIN → /retry
```

## 三条铁律

1. **不伪造执行**：没接通就说没接通，不造任务号。
2. **不用模型文字当证据**：传给反诈的是用户原文，不是模型写的 goal。
3. **失败要说失败**：部分成功要讲清哪部分成了。

## 高频追问的短答

- **套壳？** 三层不是模型的：结构校验、工具取数、证据回指。开 `validate_plan` 给他们看。
- **胡说？** 计划先校验、数据从工具取、结论带原文依据；校验不过就失败。
- **准确率？** 现在不给，需要独立标注测试集（正常/明确诈骗/信息不足/注入），报误报漏报和不确定率。
- **几个模型？** 一个学校模型，三段程序。别让人以为是三台模型。
- **跨 Agent 演示？** 演不了：P2 已实现并对前端开放（57 个操作），但 A1 还没接上它的内部接口；不演假接口，适配器已把报文形状对好。
- **加个健康咨询改哪？** `health` 在 `DOMAINS`/`SYSTEM` 里**已经映射到 a2**，模型早认识；卡在执行层——`domain_chat` 白名单、`local_domains` 客户端、A2 服务、P2 授权。全新领域才动五处。
- **你做了什么？** A1 统一入口与领域协调、旅游交互整合、反诈证据展示、联调与失败测试。模型归学校，地图归高德，A2/A3 归队友。
