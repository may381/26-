# A1 演示版范围与验收清单

| 项目 | 内容 |
|---|---|
| 模块 | A1 总智能体（统一入口 + 协调 + 出行文旅 + 反诈） |
| 版本 | 比赛演示版 v1.6（在 v1.5 界面校订基础上，补齐 P2 v3.0 接口口径），**非生产系统** |
| 适用 | 现场演示、评委问答、汇报材料直接引用 |
| 一句话 | A1 只做三件事——**接住需求、决定怎么办、把结果整合给你**；办不了的当场说明。 |

---

## 0. 一页结论

1. **A1 的边界是"协调"，不是"什么都能办"**：能判断、能拆、能派、能整合；不能替别人办，也不能假装办完。
2. **当前涉及六类外部能力，但不是每条路径都同时依赖它们**：学校模型用于综合理解与规划；8091 用于旅游；8000 用于反诈；12306 / Amadeus 只在**票务查询**时用；浏览器语音是**可选输入**。某条路径缺少它必需的依赖时**必须显式失败**，不降级成"看起来成功"；没用到该能力的路径不受影响。
3. **验收以"输入 → 实际调用 → 返回/失败提示"为准**；截图和录屏只是辅助证据，不能代替行为验收，口头描述不算证据。
4. **模型输出只是"建议"，业务完成只认领域接口的真实返回。**

## 1. A1 负责的功能

| 编号 | 功能 | A1 具体做什么 | 落点 | 演示时的一句话 |
|---|---|---|---|---|
| F1 | **需求理解** | 判断这是闲聊、咨询还是要办事；识别领域；识别缺哪些必要条件 | 学校模型 + 程序校验 | "它先判断你要什么，再决定动不动手。" |
| F2 | **任务拆分** | 输出 ASK/PLAN/REPLY；PLAN 可含多步与依赖，但执行器**只接受单步 a1 旅游/反诈**——不是单步就一步都不执行 | 计划结构 + 白名单 | "能拆成几步它都会写出来；但只要不是单步 A1 任务，就一步都不执行。" |
| F3 | **多轮协调** | 记住上一轮的限制（少走路、家人同行）；补答"杭州"能接上；任务结束后不串证据 | 会话历史 + 状态机 | "多轮不是把历史无限堆，是有边界的记忆。" |
| F4 | **结果整合** | 统一 packet：`reply` / `state` / `executionTrace` / `notificationExecuted` / `sharedMemoryWritten`；领域结果再补依据与来源 | 统一 packet | “packet 里有‘未执行通知/未写记忆’两个字段；屏幕靠执行记录和领域页脚体现，**不是界面上有个开关**。” |
| F5 | **出行文旅** | 旅游咨询（走学校模型）、生成建议行程（程序排程）、查地点/天气/交通、查票（只读） | 8091 + 程序排程 + 票务 | "咨询走模型；生成行程草案是 Java 服务 + 高德数据 + 程序排程，不让大模型自由编行程。" |
| F6 | **反诈** | 可疑文字/图片分析、风险分级、原文证据、分层建议 | 8000 反诈服务 | "它给的是辅助核对结论，不是警方认定。" |

## 2. A1 明确不做

| 不做的事 | 归属 | A1 遇到时的标准表现（照这个说） |
|---|---|---|
| A2/A3 的内部实现（健康、照护、社区、志愿、文化、能力） | A2 / A3 | "当前仅接通单步旅游咨询和反诈文本分析。跨领域、多步骤及A2/A3委派仍需P2网关，未执行任何步骤。" |
| 真实通知（短信、电话、家属、社区） | P2 / 运营 | "未发送任何通知；如需帮助请通过官方渠道联系。" |
| 活动报名 | P2 / 业务方 | "只提供信息，不代为报名。" |
| 订票、锁座、支付 | 供应商 | "只读取公开班次与票价，不锁票、不下单、不支付。" |
| 长期记忆写入 | A3 / P2 | "本次偏好仅作候选，未保存；需要您确认后才可能记住。" |
| 资金操作（转账、冻结、追回） | 银行 / 公安 | "不能代为操作资金；建议联系银行官方渠道并报警。" |
| 医疗诊断、用药建议 | 医疗机构 | "不做诊断，涉及身体不适请咨询医生。" |

> 统一原则：**不做的能力，必须让用户看见"没做"，而不是让用户以为"做了"。**

## 3. 当前可用的外部依赖

| 依赖 | 用途 | 可用前提 | 不可用时 A1 的表现 | 边界声明 |
|---|---|---|---|---|
| **学校模型 qwen3.8-27b** | 理解需求、生成计划、领域分析 | 校园网 / VPN 可达 | "模型调用或计划解析失败（原因），未执行任何业务" | 模型是共享推理引擎，不是 A1 |
| **旅游后端 8091** | 地点、天气、路线、交通、生成行程草案 | 本机启动 | "无法连接本机旅游服务（8091），请先启动对应后端" | 地图数据来自高德，非自研 |
| **反诈后端 8000** | 证据切分、案例检索、风险分析 | 本机启动 | "无法连接本机反诈服务（8000），请先启动对应后端" | 结论是辅助判断，非官方认定 |
| **12306 公开数据** | 站名、余票、票价（只读） | 公开接口可用 | "查询未成功，请以 12306 官网为准" | 可能限流/变更；不锁票、不订票 |
| **Amadeus 正式环境** | 航班查询（IATA 三字码，覆盖范围取决于供应商） | 需正式凭证 | **无凭证时明确失败**，不返回假价格 | 适配完成 ≠ 服务已开通 |
| **浏览器语音转写** | 语音转文字（可选） | 浏览器支持且有麦克风权限 | "浏览器不支持语音转写，请用文字或图片" | 浏览器能力，不是自研方言模型 |

> 补充：**端口可达 ≠ 模型可用**。状态弹窗只显示“端口可达/未连接”的端口探测结果，不证明某次模型推理成功；不要把它说成“模型已验证”。

> 接口口径：本节只列当前演示实际使用的本地接口（8091 / 8000）。P2 v3.0 的 `POST /api/v3/agent/messages`、任务查询、确认、附件、记忆、语音等是**后续对接目标**，当前 A1 没有调用 P2 `8080`；逐项对照见《A1智能体部分开发全流程_提示词与讲解手册.md》5.3～5.4。

## 4. 可演示验收标准

### 4.1 协调类（F1–F4）

| 场景 | 输入 | 正常应看到 | 失败应看到 | 判据 |
|---|---|---|---|---|
| 需求理解 | "想出去玩，少走路" | 追问城市，**不直接编行程** | 模型不可达 → 明确失败提示 | 未生成计划即不出现行程 |
| 任务拆分（单步） | 明确诈骗原文 | 计划：单步 → 反诈 | 模型超时 → "未执行任何业务" | 计划可见、领域正确 |
| 任务拆分（多步） | "想学剪纸，还要有人陪"（补充城市后） | 能拆出两步 + 依赖 | 若被要求执行 → "当前仅接通单步旅游咨询和反诈文本分析。跨领域、多步骤及A2/A3委派仍需P2网关，未执行任何步骤。" | **必须拒绝执行**，不许部分执行 |
| 多轮协调 | 先"少走路"，后补"杭州" | 保留"少走路"约束出计划 | 地点未验证 → 继续追问 | 限制不丢、地点不编 |
| 任务结束切换 | 反诈出结果后问"今天天气" | 清空旧证据域，不把旧原文当新证据；若要实时天气，需走天气工具 | 无工具数据时明确说明，**不把模型泛答当实时天气** | 旧原文不污染新任务；实时数据必须带来源与采集时间 |
| 结果整合 | 任一综合/领域问答结果 | 统一 packet：`reply`/`state`/`executionTrace`/`notificationExecuted`/`sharedMemoryWritten`；展示层补依据、来源；反诈页脚、计划保存提示等位置说明未执行事项 | 失败时保留已做到哪一步，并展开失败阶段 | packet 字段齐全；**不要求每个领域都四段式** |

### 4.2 出行文旅（F5）

| 场景 | 输入 | 正常应看到 | 失败应看到 | 判据 |
|---|---|---|---|---|
| 旅游咨询 | "杭州三日游怎么安排" | 真实地点/交通建议 + 来源 | 8091 未启动 → 明确报错 | 不出现"凭印象"的地点 |
| 生成行程 | 城市 + 日期 + 天数（1–4 天）+ 体力偏好 | 时间轴 + 每日安排；后端返回 `AMAP_ESTIMATE` 的条目才标“地图估算”。地图依赖 8091 地图配置与高德，加载失败显示提示，**不伪造地图** | 生成失败 → 明确失败，不显示旧行程 | 行程可保存/恢复，版本号递增 |
| 地点/天气 | 走"查地点 / 天气"工具；或旅游服务支持时的自然语言查询 | 真实地点、天气字段 + 采集时间 | 接口失败 → 明确失败 | 不返回编造坐标；**不在聊天框承诺"自动查设施"** |
| 票务查询 | 打开"机票 / 车票"弹窗 → 选官方站名/机场三字码 + 日期 → 查询 | 车次、席别、票价、余票、查询时间 | 无结果/限流 → 以官网为准 | **只读**，无"已购票"字样 |
| 国际航班 | 无凭证时查询 | 明确失败提示 | 不返回测试环境价格 | 缺凭证 ≠ 假数据 |

> 注：票务**不走聊天框自然语言解析**，必须在弹窗里选官方站名/机场三字码；不要把它说成"说一句话就能查票"。

### 4.3 反诈（F6）

| 场景 | 输入 | 正常应看到 | 失败应看到 | 判据 |
|---|---|---|---|---|
| 文本分析 | 合成退款保证金 + 验证码原文 | 受理 → 轮询 → 风险等级 + 原文证据 + 建议 | 8000 不可达 → 明确报错 | 受理 ≠ 完成 |
| 信息不足 | "我收到一条消息，帮我看看"（无原文） | 综合入口追问原文；防诈入口返回 needs_review | — | **不把"没证据"当"安全"** |
| 正常通知 | 免费社区读书通知（**样本回测**） | low/assessed + 仍需独立核实 | — | 不把普通通知判成诈骗；**单次回测不等于对所有正常通知的保证** |
| 图片分析 | 合成截图 | 图片可见文字 + 风险 + 建议 | 超 4MB / 非 PNG/JPEG → 明确拒绝 | 识别内容可核对 |
| 长等待 | 分析超过 3 分钟 | 提示"可手动查询原任务" | 查询失败 → 保留原任务引用 | 不重复提交、不编结论 |
| 提交不确定 | 请求超时 | "未确认是否受理，请重试原请求" | 不允许开新任务覆盖 | 幂等键复用 |

### 5.5 现场演示剧本（主线 9 幕 + 备用 1 幕）

> **怎么用这份剧本**
> - **固定文案**（按钮、状态栏、程序拒绝、失败提示）逐字照抄；**模型回复**只背“必须出现的元素”，不逐字背。屏幕措辞不同不等于演示失败，缺元素才是。
> - 每幕只做一件事。屏幕没出现预期元素时，**先停手**，按 5.5.5 处理，不继续往下点。
> - 主线按 6～7 分钟排；超时先砍第 6 幕（地图/天气），保第 8 幕（反诈）。
> - 5.5 只是现场顺序，**不替代 5.1–5.4 的验收矩阵**；该跑的失败用例仍要单独跑。

#### 5.5.1 幕前 60 秒

| 检查 | 动作 | 看到什么才算过 | 不过怎么办 |
|---|---|---|---|
| 入口 | 打开 `http://127.0.0.1:8095/` | 标题“时光链 · 问问我”，欢迎卡和输入框都在 | 8095 没起，先启动 `A1new/server.py` |
| 服务状态 | 点“智能体状态” | 弹窗“总智能体实际运行状态”；**上方两行文字**是“本地A1协调器，非P2正式网关”“本次会话内存；长期共享记忆尚未接通”，**下面才是三张服务卡**“旅游后端/反诈后端/学校模型：端口可达” | 旅游/反诈“未连接”→启动本机 8091/8000；学校模型“未连接”→检查校园网/VPN 或确认 `10.138.50.151:8000` 可达，**不能在本机启动它**；端口可达也不代表能推理 |
| 清场 | 点“开始新对话”；**本页已有对话才会弹确认框，弹了就点“确定”** | 状态栏“已开始新对话。”；页面回到初始态：欢迎语 + 两张欢迎卡 + 两条快捷问题 + 输入框 | 刷新页面，再点一次 |
| 证据 | 把第 8 幕的合成原文放在手边；确认没有真实验证码、银行卡、住址 | 原文可整段粘贴 | 用本剧本给的合成样本，不改字 |
| 回归 | 在 `a1-orchestrator` 跑 `python -m unittest -v`；在 `A1new` 再跑一次 | `Ran 60 tests` 和 `Ran 17 tests`，都以 `OK` 结束 | 数量不对先别上场，按 00 的“本次实测”核对 |
| 画面 | 浏览器缩放 100%，窗口保持演示分辨率 | 发送按钮、领域条、工具条都可见 | 不要在现场调字体和窗口 |

> 状态弹窗只证明“端口可达”，不证明模型推理成功；真正的验收是下一幕的实际返回和执行记录。

#### 5.5.2 主线 9 幕

**第1幕 · 综合入口：缺城市只问一个问题（约 30 秒）**

| 项目 | 内容 |
|---|---|
| 说什么 | “我先不说城市，只说想出去玩、少走路。” |

| 模型说出“已通知/已订票/已转账” | “这是模型措辞错误；屏幕上没有对应执行记录，以执行记录为准，未执行。” | 不要顺着圆，不要说“后台已经办了” |
| 页面卡住或状态栏不更新 | 刷新页面或点“开始新对话”；刷新不会取消后台任务 | 不要连点、不要切到别的窗口找答案 |
