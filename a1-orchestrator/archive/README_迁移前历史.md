这是独立的命令行开发原型，兼容服务器 Python 3.8，仅使用标准库，不修改现有 Java 服务。

### v3_adapter.py的用途

这是离线报文适配模块，不是已启动的HTTP服务。它读取P2 r3形状的InvocationRequest，测试A1普通追问、INPUT_PROVIDED补充和CHILD_INPUT_REQUIRED转呈；返回公共AgentResponse形状。问题ID由程序生成，不填P2的ownerTaskId/version。

```bash
python3 v3_adapter.py example_invocation.json
```

示例是固定虚构测试数据；截止日期仅供本地测试。适配器只检查使用到的必要字段，不替代完整JSON Schema、鉴权、归属和状态校验。尚未提供服务密钥校验、HTTP端点、持久收据、P2网关或动作账本，所以不能直接对外开放或宣称已完成r3接入。

需要派发任务、确认执行或其他恢复分支时，明确返回CAPABILITY_UNAVAILABLE，绝不造childTaskId或伪造执行成功。客户端测试使用mock响应；除学校模型示例外，没有接通P2/A2/A3。

当前离线模型调用固定90秒超时，适配器在不足95秒预算时拒绝启动模型。这是临时测试限制，后续HTTP服务将按真实deadline向下传播预算，不是最终协议配置。

## V0.5：可调用的A1 HTTP联调壳

新增service.py，默认仅监听服务器本机127.0.0.1:8093。保持学校模型服务和现有v2不变。不需要sudo或额外依赖。P2若部署在其他主机，需要与部署负责人另行确定访问方式，不默认向全网开放。

### 启动（每条命令单独执行）

```bash
cd /home/student_cxj/yinling-a1
python3 -m unittest -v
export A1_SERVICE_KEY="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
python3 service.py
```

该命令在终端变量中生成随机服务密钥，不输出密钥。服务启动后占用当前终端是正常现象，Ctrl+C停止；断开SSH不保证继续运行，本次不配置后台常驻。密钥用于P2调用A1，不能发给模型或放前端。正式联调由双方配置同一密钥；重启需要保留一致配置，不能每次换密钥后不通知P2更新。

另开一个终端，检查无需密钥的健康接口：

```bash
python3 -c 'from urllib.request import urlopen; print(urlopen("http://127.0.0.1:8093/health").read().decode())'
```

### 提供的接口

| 地址 | 用途 | 要求 |
|---|---|---|
| GET /health | 服务存活状态，明确p2Connected=false | 不代表学校模型或P2可用 |
| POST /internal/v3/messages | 接收r3形状任务并同步处理 | X-Agent-Key，建议X-Trace-Id |
| GET /internal/v3/invocations/{id} | 查询持久调用收据和完成响应 | X-Agent-Key |
| POST /internal/v3/invocations/{id}/cancel | 请求停止交付旧调用结果 | X-Agent-Key，按r3取消请求正文 |

收据保存在当前目录a1-receipts.sqlite3，含回复内容但不保存任务凭证或原请求全文；只存请求摘要用于幂等。此数据库属于开发数据，不要上传公共仓库或转发；尚未提供自动保留期清理。程序重启会将未结束调用标为需P2核查的失败，不自动重跑。相同invocationId同请求不重复启动，改变请求返回409；完成结果可重取。

取消不能立即终止已发出的模型HTTP计算，但会停止结果交付，调用返回后记录CANCELLED；没有业务写入，所以不发生真实业务撤销。已完成结果不因晚到取消而假装没有完成。

### 与完整r3的区别

本服务使用v3_adapter检查其已支持的字段，不是完整Schema、身份授权及所有状态的实现。仅支持普通追问、补充回答、子问题转呈和简单回复。PLAN需要真实P2委派时返回503/CAPABILITY_UNAVAILABLE；其他尚未接入的恢复分支也明确拒绝，不模拟成成功。

尚未接P2步骤、动作、委派、共享记忆与权限服务；无真实通知、报名、图片处理。默认模型调用90秒，剩余预算不足95秒时拒绝启动，仅用于测试；全局模型限流、完整Schema校验和逐调用时限控制需继续完善。不要将当前接口壳视为生产可用或首批v3全部完成。

### 发给后端的联调信息

A1提供本机8093的任务接收、收据查询和取消接口。当前可测试鉴权、重复调用、追问报文与收据恢复；委派接口尚未连接。请P2提供mock网关地址、A1允许使用的工具及已确认的请求样例，双方按密钥配置进行连接。不要把a1.py --chat或demo.py当作已运行的HTTP服务。

### 并发保护补充（2026-10-31）
当前HTTP联调壳每进程最多一个处理调用，其他新调用返回HTTP429/RATE_LIMITED，并留下FAILED回执；不重复启动模型。P2应先查收据，确认该调用未执行，再使用新的invocationId安排下一次调用。取消和回执查询不占用模型执行位。不是跨进程分布式限流。

### 本机领域联通演练
运行 python local_domains.py，使用 /travel 文字 调用8091旅游后端，/fraud 可疑文字 调用8000反诈后端，/status读取分析任务，/retry复用丢响应提交的幂等键。仅连接固定loopback地址并保留旅游Cookie。不会猜测执行动作，不是P2 v3网关，也不表示共享长期记忆已接入。/new同时清除当前任务与待重试引用，不取消后端任务。提交结果不确定时禁止用新文本覆盖待重试请求；先/retry复用同一幂等键。反诈分析会在原模块生成本地分析记录，不发送家属通知。

### SSH重新连接后的启动
service.py优先使用A1_SERVICE_KEY；未设置时读取程序目录的.a1-service-key。Linux文件权限必须为600。不自动生成、不打印密钥；共享交付包排除密钥文件。已有私有文件时可直接python3 service.py，无须每次export。


### 回答归属校验
INPUT_PROVIDED 必须携带 responseTo（ownerTaskId、UUID v4 inputRequestId、正整数 version、selectedOptionId）。当前A1根任务只接受归属于自身的回答；子任务回答应由P2恢复相应子任务，A1不会重新规划根任务。子问题转呈校验问题字段后原样保留ID与内容。任务树权限、全局问题唯一性与版本状态仍由P2确认，当前适配器不替代完整Schema。


### A1自然语言领域联通入口

运行 `python domain_chat.py`，或根目录比赛启动菜单选择6。此入口使用学校qwen3.8-27b规划，只接通本机8091旅游咨询、8000反诈文本分析。先启动相应领域服务，再输入自然语言需求；缺信息由学校模型追问。旅游向导、行程编辑仍使用原网页，本入口不会代替网页完成预订。

程序只自动执行单步、归属A1的旅游咨询或反诈文本计划；用户原文与补充信息原样合并传递，不使用模型生成目标作为证据。多步骤、A2/A3、共享记忆等尚未接通时不执行任何部分。反诈受理后 `/status` 轮询原任务；受理结果未知时 `/retry` 复用原键，不重新调用规划模型。`/new` 只清空A1本地引用，不取消或删除后端任务。尚未提供P2统一身份、跨Agent持久恢复、自动多任务执行或学校网络下的端到端验收。
