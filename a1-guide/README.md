# A1「说」：Spring Boot 第一版

独立联调工程，遵循上级目录《底座契约_v1.md》的 `/api/agent/messages` 请求与响应格式。支持本地 Ollama 根据演示资料生成自然讲解。

## 启动

需要 Java 17 和 Maven。当前使用 Spring Boot 3.5.7，正式部署前应更新到团队认可的维护版本。

首次构建，在此目录打开 PowerShell：

```powershell
cd server
mvn clean package
java -Dfile.encoding=UTF-8 -jar target/a1-guide-0.1.0.jar
```

如果已经有构建好的 jar，双击本目录 `start.cmd`，或运行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`。

启动后浏览器打开 **http://127.0.0.1:8091/**。窗口按 Ctrl+C 停止。
默认只监听本机，不对局域网或公网开放。端口冲突时可设置 `$env:PORT='8092'` 再启动，并访问新端口。

开发验证时为避免改动全局 Maven 仓库，实际使用了：

```powershell
mvn '-Dmaven.repo.local=D:\Desktop\26挑战杯\.m2-repository' clean package
```

## 本地 Ollama 接入

默认连接 `http://127.0.0.1:11434`，模型 `qwen3.5:4b`（本机已安装）。先确认 Ollama 正在运行，再启动本工程。使用官方 `POST /api/chat`，非流式请求、关闭思考输出，只读取回答字段，不展示模型思考过程。

可在启动服务前设置：

```powershell
$env:OLLAMA_MODEL='qwen3.5:4b'
$env:OLLAMA_BASE_URL='http://127.0.0.1:11434'
$env:OLLAMA_TIMEOUT_SECONDS='90'
$env:OLLAMA_KEEP_ALIVE='30m'
```

地址只允许本机 HTTP 服务。设置 `$env:OLLAMA_ENABLED='false'` 后重启可切回纯规则版本；默认启用模型，模型失败明确返回 HTTP 502 `UPSTREAM_ERROR`，不会默默用规则答案冒充模型输出。服务启动后会在后台预热一次模型，首个问题不再承担冷启动加载；预热失败只记警告、不阻塞启动。`OLLAMA_KEEP_ALIVE` 默认 `30m`，避免演示中途停顿超过 5 分钟就卸载模型、下一次提问又变慢。`OLLAMA_TIMEOUT_SECONDS` 是单次生成的上限而非典型等待时间；最多同时生成一条，繁忙时提示稍后重试。

景点讲解和设施/时间回答由模型根据检索资料组织语言；普通问候、身份询问和旅行闲聊也可以进入本地模型，不再用统一的“没有可靠资料支持”打断交流。求助、未知位置、未开放服务、没有设施记录的问题继续使用确定性提示。工具记录保留实际查到的资料，界面用独立来源文字标注演示内容；不在每次设施回答中重复定位和路线技术声明，开放时间仍明确提示非实时。提示词约束不能保证生成内容零错误，仍需人工验收；真实信息需要换成核实后的资料。

支持短期上下文：先问“腿走酸了”再回答“荷香池”，会继续查休息设施；先问“介绍清风亭”，再问“那里能坐吗”，会查询清风亭的休息设施。“详细讲讲”“简单点”继续讲同一主题；“说慢一点”将 speechRate 调为 0.65，“正常语速”调为 1.0，播放仍由 P1/P2 完成。

上下文保存地点 ID、待澄清/上一个主题、临时表达风格与语速，以及最近 3 轮成功的旅游/闲聊对话，每条最多 400 字。只在服务端内存中短暂保留，不落盘、不写入 A3 长期记忆。自由聊天向本机 Ollama 发送当前问题和这一小段历史；景点查询仍只发送当前问题、资料和参考回答，不发送 userId/tripId。未接入图片输出或真实景区图片库。

用户问“你知道我是谁吗”时，模型可以参考最近聊天中用户自己说过的称呼；没有提供过则如实询问如何称呼，不从 mock 用户 ID 推断身份。用户明确自我介绍后的称呼复述由程序校验并组织，避免模型把用户和助手的名字弄反。短期称呼回忆不是读取真实档案或已保存长期记忆。资料没记载某个典故时，应说“还没查到相关资料”，不能说“这里没有历史故事”。

## 连续对话的临时会话约定

- JSON 请求/返回字段与底座契约保持一致；本原型用服务端 HTTP Session 保存上下文，通过 `JSESSIONID` Cookie 延续。
- 按浏览器会话 + userId + tripId 隔离；同一浏览器里的同一用户同一旅程共享一份临时上下文，不是每个标签页独立。
- 闲置 20 分钟失效，重启服务全部清空；每个 Session 最多保留 8 个用户/旅程范围，超出时移除最久未使用的一份。
- 发送“重新开始对话”清空当前范围的对话窗口、地点和偏好；网页“开始新对话”按钮发送同一命令，成功后才清屏。求助与跨业务话题会清理待补充问题；求助对话不加入最近聊天窗口。
- “那里”优先指刚聊的景点；“这里”或直接询问设施优先使用已提供位置。新的有效/未知位置会取代旧位置，主动传空位置会取消先前由 context 提供的位置。
- 模型失败不提交本轮上下文；延迟到达的模型结果不能覆盖较新的清空/求助状态。

**P1 联调**：网页同源请求自动携带 Cookie。uni-app 端需要确认运行平台是否自动延续 Cookie；若没有，后续请求需带上服务端返回的会话 Cookie。不要把所有老人共用一份 Cookie。没有 Cookie 时接口仍可单轮回答，但没有连续上下文。推荐通过统一后端/同源代理访问，当前没有为任意跨域来源开放 CORS。

这只是第一阶段本机联调的临时上下文实现，不是用户认证。生产环境应由 P2 绑定真实身份；多实例会话和独立聊天编号由团队后续按契约变更流程统一。本工程不擅自增加 conversationId、图片等冻结字段。

## 这一版能做什么

- 文字问答和页面快捷问：讲解、厕所、休息处、饮水处、出口、开放时间、路线。
- 以请求中的景点 ID 或问题里的景点名称查询资料；位置未知时追问，不编距离。
- 返回 `speechRate: 0.8`，供后续慢语速播放使用；`audioUrl` 固定为 null。
- 求助意图返回 `human_handoff`，选择 family/scenic；没有创建 HelpEvent、发送通知或改变旅程。
- 健康、反诈、关怀、文化、社区、志愿、技能服务仅作关键词路由，明确提示未开放。
- 输入校验和统一错误格式；问答资料来源可在 `tools` 中查看。
- 路线问题（“哪条路线省力”“台阶多的路线”）返回 `route.recommend` 工具记录，按共享样本逐条列出台阶数、步行时长和休息点数。回答不给距离、不做导航承诺、不声称已更改路线，也不冒充按个人档案算出的个性化推荐。

**本版是本地模型＋规则检索＋演示知识库。** 支持有限的短期上下文；不具有长期记忆、真实定位、实时营业查询、情绪识别、真实语音识别或合成能力。口语识别仍为短语规则，不等于任意语句都能理解，尤其不能成为唯一求助入口。

测试页是 Spring Boot 自带的浏览器联调页，不是新的 uni-app 客户端。

体验页支持手机/电脑自适应：右侧提问气泡、正文式回答、固定底部输入框、大字模式、复制回答、生成中提示和滚动到最新消息。回答可以自然分段，支持有限的安全文本格式（加粗、列表、小标题、引用和代码）；不执行模型返回的 HTML，不自动加载模型文本中的链接或图片。回车发送，Shift+回车换行，中文输入法选词时不发送。原始接口结果收在侧栏的“联调详情”。

## 给 P1 的接口

```http
POST /api/agent/messages
Content-Type: application/json
```

```json
{
  "userId": "u100",
  "text": "厕所在哪里？",
  "context": { "tripId": null, "location": "spot-003" }
}
```

`intent` 可不传；若传，必须为契约定义的枚举。明显求助关键词优先于客户端的意图提示。`context` 可省略，`location` 使用景点 ID，不是经纬度；`tripId` 原样作为上下文保留在请求中，本版不查询或修改旅程。

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "intent": "tourism",
    "text": "【清风园演示数据】资料记录：荷香池卫生间，池边服务点。未接入实时定位，不提供距离或导航承诺。",
    "speechRate": 0.8,
    "audioUrl": null,
    "tools": [{ "tool": "knowledge.search", "args": {"query":"厕所在哪里？"}, "result": {"source":"MOCK", "records":[]} }],
    "handoff": null
  }
}
```

上面 `records` 为简写，实际返回命中的演示记录及其来源元数据。`userId` 必填，本版仅进行格式校验、不鉴权、不读取用户档案；符合阶段一 mock 身份联调范围，不能直接用于生产用户数据。

## 与队友对接

- **P1**：录音先调用 P2 的 ASR；转写文本调用本接口；再把回答和 speechRate 发给 P2 的 TTS。当前测试页只有文字。暂停/继续播放属于播放器能力。
- **P2**：后续把本包合并进统一后端，或提供 ScenicDataProvider 实现；档案、真实权限、旅程、语音不在本工程重复实现。
- **A2**：接收 handoff，通过正式求助服务建立事件并返回真实处理状态。本接口仅给出转交意图，不执行通知。
- **A3**：后续通过约定的记忆工具提供经确认偏好；本版不存储对话、不自动回写记忆。

`ScenicDataProvider` 目前仅由 `MockScenicProvider` 实现。`DATA_SOURCE=real` 会拒绝启动，防止把 mock 冒充真实数据。工具名 `knowledge.search` 对应实际 Provider 查询，`route.recommend` 只回显共享样本里的路线事实；没有虚构 `help.create` 或 `memory.write` 执行记录。

`fixtures/qingfeng.json` 提供 1 景区、3 路线、6 景点、10 设施，每条带来源元数据。路线数据兼作后续共享样本：A1 只按资料列出台阶数、步行时长、休息点数，按体力挑一条、读取档案筛选这类个性化推荐仍归平台路线接口（P2，N3），本工程不实现。景点/设施附加字段是本工程演示数据结构，需 P2 确认后再作为团队统一数据结构，不视为修改已冻结契约。

## 验证

在 server 下执行 `mvn test`。测试覆盖回答来源、未知位置、休息与求助不冒称已执行、未开放意图、非法输入、禁止 real 回落 mock、数据数量和测试页面；新增追问补充、代词指向、用户/浏览器/旅程隔离、到期与容量、手动清空、失败回滚、晚到结果、讲解风格、否定短语、路线问题不改路线、讲解词不为空、模型预热与关闭预热等场景。模型客户端使用模拟响应检查请求内容、格式错误、上游失败与约束说明保留，自动化测试不依赖本机模型在线。

手动验收：选择荷香池→问厕所；切换未知位置→问休息；问关门时间→确认演示提示；输入“求助，联系家属”→确认 handoff 为 family 且没有通知成功提示。
